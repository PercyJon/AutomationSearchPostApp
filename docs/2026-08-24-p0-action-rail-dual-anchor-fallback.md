# P0：右侧动作栏双锚点视觉回退（2026-08-24）

## 修复前记录

- 当前错误现象：视频右侧评论气泡在半透明叠加到不同视频背景时，评论模板可能无法确认；评论数为零或 OCR 受背景干扰时，数字栏几何也可能没有足够证据。无障碍动作栏节点缺失时，运行时只能安全跳过该视频。
- 稳定复现步骤：使用当前抖音版本的右侧动作栏截图，在构造的 `ScreenContext` 中移除可用无障碍图标列、评论模板确认和 OCR 数字栏几何；现有 `VideoCommentButtonDetector.find(...)` 返回空目标。
- 当前预期行为：仅当点赞图标和收藏图标作为两个独立视觉锚点，处于同一右侧比例栏位、尺寸/间距一致、并在连续两帧稳定后，才以它们之间的比例位置推导评论图标；点击后仍须确认评论面板。
- 实际行为差异：当前实现只支持“评论气泡模板”或“OCR 数字栏”视觉证据，不能在上述条件下形成安全评论入口。

## 本轮唯一根因假设

评论入口的视觉回退缺少相邻、独立且有固定槽位顺序的图标证据；当气泡自身或数字栏不可靠时，无法区分“未识别”与“可由已确认邻居唯一定位的评论槽位”。

## 最小修改边界

1. 只为已有 `comment_next_video_rail` 截图增加点赞、收藏两个 Alpha 感知模板匹配；分享图标不作为本轮点击锚点。
2. 只有两个锚点都命中、同栏、同尺度、间距满足屏幕比例，并在两张连续截图中稳定，才生成评论中点候选。
3. 新候选排在现有无障碍、评论气泡模板、OCR 数字栏之后；仍经过视频页、下一视频指纹与评论面板后置确认。
4. 不新增固定像素点击点，不放宽 OCR 文本点击，不改变手势、超时、评论恢复或消息路径。

## 待验证

- JVM：双锚点缺失/错位/不稳定必须拒绝；同栏稳定双锚点才允许产生评论候选；已有入口优先级不变。
- 真机：OnePlus NE2210 / Android 16，以 `designer × 3 × 1` 自然路径验证；日志不得出现点赞、收藏、分享点击，且评论面板必须在候选点击后确认。

## 第 1 轮阶段性结果（设备重新连接前）

- 修改内容：已加入点赞、收藏两个 Alpha 模板资产和匹配器；候选必须经历独立模板匹配、同栏/同尺度/两槽位间距校验、两帧稳定，再排在无障碍、评论气泡模板和 OCR 几何之后。分享图标没有进入证据链。
- JVM：`CommentSurfaceSignalsTest` 通过，覆盖未确认、反序/异尺度拒绝、两帧稳定、中点推导及既有模板/OCR 优先级。
- Android 设备侧：`AlphaMaskedActionIconMatcherInstrumentedTest` 在 OnePlus NE2210 / Android 16 通过。它只在本地 `Bitmap` 上验证 APK 资产和 Android `AssetManager`/`Bitmap` 匹配，不会打开抖音或执行无障碍动作。
- 真机自然路径：`designer × 3 × 1` 已完成，3 位用户均为 `BLANK_PROBE_VERIFIED`；第 2 个视频以既有 `ocr_fallback` 打开评论面板。所有记录的动作槽均为 `wait_ms=0`，未记录点赞、收藏、分享动作或真实消息。
- 观察结果：本轮自然路径没有记录 `action_rail_dual_anchor_candidate` 或双帧确认，因此没有把双锚点作为已实机点击验证。拉取的当前受限截图中，至少一张按与代码同一比例/阈值离线复核可同时得到点赞约 `0.973`、收藏约 `0.993`；这与运行日志缺少候选事件不一致，尚不能据此宣布该回退生效。
- 本轮结论：整体路径改善（3 视频完整完成），但“双锚点实际回退被触发”无变化，仍待单独确认。

## 第 1 轮完整结果（恢复连接后）

- 真机与路径：OnePlus NE2210 / `b33aa309` / Android 16，抖音当前已在系统弹窗中被操作者授权由本项目调起；使用“搜索指定用户 `designer`、3 个视频、每视频 1 名用户”的同一自然路径。
- 启动前置情况：第一次未确认系统的“允许本 App 调起抖音”弹窗时，流程在 `WAITING_FOR_HOME` 安全暂停，未进入任何视频或动作栏识别。操作者确认后，第二次同配置路径正常进入搜索、用户主页、视频、评论面板和返回链路；这不是双锚点的识别失败。
- 双锚点证据：第 2 个视频记录了 `like_available=true`、`collect_available=true`，并产生候选：点赞置信度约 `0.973`、收藏约 `0.993`，归一化中心纵坐标约 `0.564 / 0.736`，横向偏差为 `0`。第 3 个视频再次独立产生候选：约 `0.991 / 0.905`，纵坐标约 `0.566 / 0.736`，横向偏差约 `0.00046`。
- 稳定与优先级：两个视频中，既有 OCR 数字栏已在第一个可用动作栏截图安全找到评论入口，因此运行时按既定优先级立即交给 `ocr_fallback` 并成功确认评论面板。双锚点在各自过渡探测中只得到首帧证据，未达到第二帧稳定、没有越级点击，也没有出现 `source=dual_anchor_fallback`。这正是“已有更高优先级证据时不抢占”的预期行为。
- 任务结果：3 个视频均完成，3 位评论用户均为 `BLANK_PROBE_VERIFIED`；日志没有点赞、收藏、分享动作或真实消息发送。最后记录为 `comment_video_batch_completed [video_count=3]` 与 `comment_runtime_terminal [outcome=COMPLETED]`。
- 本轮结果：**改善**。先前“离线图像命中但真机没有候选日志”的不一致已定位为当时采样帧中动作栏未显现；新诊断显示隐藏帧会得到 `like_available=false`，而右栏显现的稳定帧可在真机匹配两个锚点。尚未在“节点、评论模板和 OCR 均失败”的真实场景中实际点击双锚点推导位置，因此不把它宣告为已实机点击验证。
