# 抖音自动化营销 App — M2.5 产品与任务模型设计

状态：设计中（v0.1）  
基线：M2 `62fa06b`  ���

M2.5 的目标不是新增自动化动作，而是把当前“单次关键词 POC”整理为可配置、可恢复、可审计的任务系统，为 M3 编码提供稳定的数据结构和界面边界。

## 1. 设计原则

- 任务配置在启动时生成不可变快照；运行期间修改预设或规则，不影响当前任务。
- 搜索词、地区和屏蔽词都使用语义字段，不在业务层写死坐标或页面位置。
- 屏蔽判断发生在打开用户主页之前，命中后直接记录并跳过。
- 无法获得可靠用户身份时暂停并人工确认，不盲点、不发送。
- M2/M3 默认仍为安全探测模式，只提交一个 ASCII 空格，不发送真实文案。
- 预设数据支持远端接口、私有缓存和本地兜底，接口不可用不能阻塞已有任务。

## 2. App 功能板块

### 2.1 首页/任务工作台

首页按正常业务 App 设计，不展示原始调试信息，不直接显示 Node 数量、OCR 文本、内部状态枚举、Hash 或坐标。

**顶部区域**

- App 名称和简短副标题
- 无障碍状态 Chip：已连接/需要授权
- 设置入口

**主操作区域**

- 无任务时：突出“新建任务”按钮和最近使用的搜索词
- 有任务时：显示任务名称、当前搜索词、地区、执行进度和状态
- 运行中提供“暂停”；暂停后提供“继续”和“停止”
- 所有异常使用普通用户可读的中文提示，并提供“查看详情”入口

**统计卡片**

- 已处理用户
- 已跳过用户
- 失败用户
- 当前任务耗时

**任务列表**

- 最近任务按时间倒序排列
- 显示任务名称、搜索词摘要、状态、更新时间
- 点击任务进入任务详情，不直接进入调试页

**底部导航**

```text
任务（首页） | 记录 | 设置
```

诊断截图、Node dump、OCR、Logcat 和内部状态仅从“设置 → 诊断”进入。诊断页仍可保留开发期间的调试按钮，但不作为首页主要内容。

首页必须覆盖四种状态：无任务、准备执行、运行中、暂停/异常。无障碍未授权时只显示明确的授权提示和跳转按钮，不自动反复拉起设置页。

### 2.2 新建/编辑任务

- 任务名称
- 预设搜索词（可多选）
- 自定义搜索词
- 地区选择（单选，预留多选）
- 屏蔽关键词
- 最大处理用户数
- 安全探测/真实发送模式
- 消息模板（M2.5 只保存，不发送）
- 任务预览：显示最终搜索词和规则摘要

### 2.3 预设搜索词

- 远端读取的预设词列表
- 本地缓存和更新时间
- 手动刷新
- 接口失败时使用上次缓存
- 缓存为空时使用内置最小预设
- 预设词版本号，保证任务快照可追溯

### 2.4 规则管理

- 屏蔽关键词列表
- 启用/停用规则
- 规则命中字段：名称、抖音号、用户行元数据、OCR 文本
- 当前版本先使用“包含”匹配，不开放正则表达式
- 规则命中后展示原因并记录，不进入主页

### 2.5 运行详情

- 当前阶段：搜索、用户列表、主页、私信页、返回列表
- 当前用户状态：处理中、已跳过、探测成功、失败、需人工处理
- 已处理/跳过/失败数量
- 当前搜索词和地区
- 当前规则命中信息
- 最近诊断截图、Node dump、OCR 和日志入口

### 2.6 历史与诊断

- 任务历史
- 用户处理记录
- 失败原因筛选
- 导出脱敏诊断包
- 清理截图、OCR 和 Node dump

### 2.7 设置与设备

- 无障碍服务入口
- 目标抖音包名和版本
- 设备兼容性检查
- 安全模式开关（真实发送默认关闭）
- 日志保留策略

## 3. 任务模型

### 3.1 任务配置

```text
TaskDraft
  id
  name
  presetIds[]
  customKeywords[]
  region?
  blockedKeywords[]
  maxUsers
  messageTemplate?
  executionMode = SAFE_BLANK_PROBE | REAL_SEND_REQUIRES_CONFIRMATION
```

### 3.2 任务快照

任务开始时把 Draft 转换为 Snapshot：

```text
TaskSnapshot
  taskId
  presetVersion
  baseKeywords[]
  region?
  composedQueries[]
  normalizedBlockedKeywords[]
  maxUsers
  messageTemplate?
  executionMode
  createdAt
```

运行中的自动化控制器只读取 Snapshot，不直接读取正在编辑的 UI 状态。

### 3.3 用户处理记录

```text
TaskUserRecord
  taskId
  identityKeyHash
  displayNameHash?
  accountHandleHash?
  query
  outcome
  reason?
  startedAt
  finishedAt?
  pageRoute?
```

原始用户名称、抖音号和 OCR 文本不写入普通日志；诊断文件保存在 App 私有目录。

任务状态：

```text
DRAFT → READY → RUNNING → PAUSED → RUNNING
                         ├→ COMPLETED
                         ├→ STOPPED
                         ├→ MANUAL_HANDOFF
                         └→ FAILED
```

## 4. 搜索词组合规则

用户示例：

```text
地区：广东
基础词：红木家具
最终搜索词：广东红木家具
```

组合算法：

1. 去除首尾空白，统一 Unicode 标点和空白。
2. 地区为空时，最终词等于基础词。
3. 基础词已经以该地区开头时，不重复添加地区。
4. 否则将地区前置，不插入额外空格，生成抖音输入框实际文本。
5. 多个预设词生成多个查询项，任务按顺序处理。
6. 任务预览必须显示最终文本，避免用户误以为搜索的是基础词。

## 5. 屏蔽关键词规则

例如：

```text
屏蔽词：工厂
用户名称：北流市某某实木大板厂
结果：命中屏蔽规则，跳过，不进入主页
```

匹配前统一：

- 去除空白和常见标点
- 中文不区分大小写场景；英文使用大小写折叠
- 兼容 OCR 的省略号、分隔点和全半角字符

默认检查字段：

1. 用户显示名称
2. 抖音号/账号标识
3. 用户行中可识别的地区、公司和店铺信息
4. 同一用户行范围内的 OCR 文本

规则优先级：

```text
可靠身份缺失 → 暂停人工确认
命中屏蔽词   → FILTERED_BY_KEYWORD，记录并跳过
回关         → FOLLOW_BACK_SKIPPED
已处理       → DUPLICATE_SKIPPED
其他         → 进入主页
```

屏蔽规则不能用于绕过验证码、风控或平台安全提示；它只决定业务上的用户筛选。

## 6. 预设词接口与缓存

建议接口：

```http
GET /v1/search-presets?deviceProfile={profile}&locale=zh-CN
```

响应最小字段：

```json
{
  "version": "2026-08-18.1",
  "items": [
    {"id": "redwood-sofa", "label": "红木沙发", "keyword": "红木沙发", "enabled": true}
  ],
  "updatedAt": "2026-08-18T00:00:00Z"
}
```

客户端策略：

1. 启动或手动刷新时请求接口。
2. 成功后保存版本和缓存时间。
3. 请求失败时使用最近缓存，并在 UI 显示“使用缓存数据”。
4. 没有缓存时使用内置只读预设。
5. 任务快照保存 `presetVersion` 和最终搜索词。

M3 可先实现本地 Mock 数据源和缓存接口，待模型稳定后再接正式后端。

## 7. 与当前自动化链路的衔接

```text
TaskSnapshot
    ↓
QueryComposer
    ↓
抖音搜索与用户标签
    ↓
UserResultIdentityExtractor
    ↓
BlockedKeywordEvaluator
    ├─ 命中：记录并选下一位
    └─ 未命中：进入主页
          ↓
      私信入口与安全探测
          ↓
      TaskUserRecord + 断点锚点
```

现有 M2 的 PageDetector、Selector、OCR、翻页锚点和空白消息安全探测继续作为底层执行器，不在 M2.5 重写。

## 8. M2.5 完成标准

- 能画出并实现上述功能板块的基本导航。
- 一个任务可以从预设词、地区和屏蔽词生成不可变 Snapshot。
- `广东 + 红木家具` 正确生成 `广东红木家具`，不会重复添加地区。
- 包含“工厂”的用户在进入主页前被跳过并留下记录。
- 规则文本经 OCR/节点两种来源输入时结果一致。
- 预设接口失败可以使用缓存，不影响已有任务启动。
- 任务重启后可以读取快照和已处理用户记录。
- 当前安全探测链路仍不发送真实消息。

## 9. M3 编码顺序

1. 定义 Kotlin domain models、QueryComposer 和 BlockedKeywordEvaluator。
2. 为现有 `AutomationStore` 增加 TaskDraft/Snapshot/Record 状态。
3. 先接本地 Mock 预设源和缓存，再实现正式接口适配层。
4. 更新 Compose UI：任务创建、预览、规则和历史记录。
5. 将规则评估接入用户行选择前。
6. 添加 JVM 回归测试和脱敏真机夹具。
7. 真机只运行空格安全探测，确认记录、跳过和断点续接。
