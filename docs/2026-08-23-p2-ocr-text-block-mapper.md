# 2026-08-23：P2-D OCR 文本块映射职责抽取

本记录遵循项目根目录 `AGENTS.md` 的小步修改与同路径验证要求。

## 当前差异

- 现象：无障碍服务和导航控制器各自维护相同的 OCR 文本块映射逻辑。
- 稳定复现：页面 OCR、用户结果身份 OCR、私信空白探测 OCR 与诊断 OCR 都会把 OCR 边界转为 `ScreenBounds`。
- 预期：空边界和逆序边界在所有入口得到同一份框架无关的 `OcrTextBlock`。
- 实际：两个实现位置容易在后续修改中产生不同的 OCR 几何证据。

## 本轮唯一根因假设

OCR 结果适配重复存在于两个组件，导致同类 OCR 证据存在语义漂移风险。

## 最小修改与验证

- 新增 `OcrTextBlockMapper`，迁移既有空边界和边界排序逻辑；所有 OCR 调用时机、区域与后续状态机均不变。
- 第一轮 JVM 单测直接构造 Android `Rect` 时，框架替身返回全零边界；根因确认后，未改动生产映射，而是将整数边界排序暴露为无 Android 依赖的纯函数进行覆盖。
- 风险：OCR 边界排序或空边界表示发生变化。
- 验证：文本保留、空边界、逆序整数边界单测；完整 Debug 单测、Lint、构建；真机干跑验证用户结果 OCR 与评论候选路径。

## 验证结果

- 结果：改善。首轮测试夹具因 JVM Android `Rect` 替身失败；同一根因下的最小测试调整后，定向与完整测试均通过，生产规则未改变。
- 真机：OnePlus NE2210（Android 16 / SDK 36，设备序列号 `b33aa309`）；`designer`、匹配词“不错”、任一匹配、1 个视频 / 1 位用户、干跑。
- 关键日志：用户结果身份 OCR 返回 `38` 个文本块，随后完成目标主页、首个作品、评论面板与候选选择，终态 `COMPLETED`。
- 安全与几何检查：未进入评论用户主页、私信或空白消息探测；未新增 Android 几何尺寸、固定 px、坐标点击或手势逻辑。
