# 2026-08-25：评论私信表单文案与任一匹配

## 修复前记录

- 错误现象：评论私信创建页仍使用旧字段名，并暴露匹配方式双态；匹配词提示为 `|` 分隔。
- 稳定复现步骤：首页 → 评论私信，查看表单标签、占位符、匹配方式与跳过置顶位置。
- 预期行为：用户昵称、匹配词提示“多个词用，分隔”、无匹配方式、视频数、评论数，跳过置顶在表单项最后；匹配逻辑统一为任一匹配。
- 实际行为差异：标签为“目标用户 / 视频上限 / 每视频人数”，匹配方式可见，跳过置顶在用户字段后。

## 本轮唯一根因假设

表单文案和匹配入口仍是旧产品契约；运行时仍会读取已持久化的 ALL 模式。

## 最小修改范围

1. 更新评论私信表单标签、占位符和字段顺序。
2. 匹配词按中文逗号、英文逗号和历史 `|` 拆分。
3. 新建、复用和运行时一律使用任一匹配；ALL 仅作为旧记录反序列化值保留。

## 几何与安全检查

- 未新增固定 px、点击坐标或手势时长。
- 空白探测语义不变；点击顺序不变。

## 验证结果

- JVM：中文逗号、英文逗号、历史 `|` 拆分与强制任一匹配用例通过。
- 构建：`testDebugUnitTest`、`lintDebug`、`assembleDebug` 通过。
- 真机：OnePlus NE2210 / `b33aa309` / Android 16。创建页显示“用户昵称 / 匹配词 / 视频数 / 评论数 / 跳过置顶”，不存在匹配方式控件，跳过置顶位于表单项最后。
- 同一真机任务使用“室内设计师 / 视频数 2 / 评论数 3 / 跳过置顶开启”，最终已处理 6 / 跳过 0 / 失败 0，均为 `BLANK_PROBE_VERIFIED`。
- `p0_regression_preset_applied`、`comment_runtime_started` 和首视频选择日志均确认 `skip_pinned=true`。本次目标主页首屏没有可见“置顶”标记，因此自然路径未触发实际跳过；已有 `CommentEntryStateMachineTest` 继续覆盖开启时排除带“置顶”标记并选择下一视频卡片。

本轮结果：**改善**。表单与统一任一匹配契约已生效，完整空白探测流程通过；跳过置顶的配置传递和离线分支通过，但自然置顶样本前置条件未出现。
