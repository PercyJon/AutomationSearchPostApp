# P2-I：本地队列终态路由策略

日期：2026-08-24
范围：仅抽取任务终态后的本地队列去向；不改变终态动作或自动化页面链路。

## 修改前记录

- 当前现象：任务完成、失败或达到上限后，控制器会正确发布终态、决定是否回记录页，并在队列中间项延后启动下一任务；但“下一项 / 队列完成 / 普通任务结束”的路由条件和状态发布、延时调度、任务启动混在同一方法中。
- 稳定复现步骤：
  1. 运行单个任务至任意终态；
  2. 运行两项同类型本地队列，使第一项到达任意终态；
  3. 使最后一项到达终态。
- 预期行为：单任务回记录页；队列中间项不提前回记录页并顺序启动下一项；最后一项持久化为完成队列并回记录页。
- 实际差异：当前行为正确，但上述纯分流不能独立覆盖，后续维护时容易让发布和后续调度条件分离。

## 本轮根因假设

终态去向的纯条件嵌在有副作用的控制器方法中，缺少对全部队列存在性和后续任务存在性组合的单测。抽取策略即可锁定行为，而不触碰稳定的发布、延时或启动动作。

## 最小修改

- 在 `TaskQueue.kt` 增加：
  - `LocalTaskQueueTerminalRoute`：`START_NEXT_TASK`、`COMPLETE_QUEUE`、`FINISH_STANDALONE`；
  - `LocalTaskQueueTerminalPolicy.route(...)`：根据“是否有后续冻结任务”和“是否存在本地队列会话”返回唯一去向。
- `DouyinNavigationController.publishTaskTerminal(...)` 只消费策略结果：
  - 仍按原逻辑发布成功/失败相位；
  - 仍由 `scheduleNextQueuedTask()` 延时启动下一项；
  - 仍由 `LocalTaskQueueSession.advance()` 持久化最后一项完成；
  - 不修改节点、OCR、手势、消息或队列 FIFO。
- `TaskQueueTest` 覆盖四种布尔组合，确认有后续任务优先级高于本地会话存在性。

## 结果

- 结果：改善。终态路由成为可独立验证的纯策略，控制器保留所有既有副作用和顺序。
- 自动化验证：
  - `./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug` 通过；
  - `git diff --check` 通过。
- 真机验证：OnePlus NE2210（`b33aa309`）。更新 APK 后本项目无障碍服务正常重新连接；历史停止态仅恢复记录，不产生 `task_started`，没有自动续跑。P0 阶段已对中间项顺序进入下一任务、最后一项回记录页完成真实设备验收；本轮未改变这些动作路径。

## 几何检查

- 本轮没有新增或修改 Android 几何尺寸、固定像素、比例坐标或手势参数。
- 因此没有 dp 归一化新增项；现有安全门及稳定链路均不变。
