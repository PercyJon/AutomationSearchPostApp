# 任务表单视觉收敛记录

## 开始前记录

- 当前现象：B 端用户私信与评论区私信的任务表单含有多段辅助小字；输入控件采用较高的下划线样式，操作按钮为大号胶囊形，整体密度偏低。
- 稳定复现：登录后从首页分别进入“B 端用户私信”和“评论私信”任务创建页。
- 预期行为：两页仅保留字段标签、输入/选择控件、必要校验和操作按钮；采用紧凑、圆角矩形的统一表单样式，且不改变任何任务字段、默认值、校验或启动逻辑。
- 实际差异：静态说明文字和大尺寸控件使页面显得粗糙，也增加了滚动距离。
- 本轮唯一假设：问题来自任务表单的展示层级与组件比例，而不是任务状态或自动化执行逻辑。
- 修改边界：仅调整 `HomeScreen.kt` 中两类任务表单的静态文案、尺寸和展示样式；不修改任务数据模型、校验、保存、启动、无障碍或网络逻辑。

## 验证计划

1. 编译、单元测试和 Android lint。
2. 安装到已连接真机，分别检查两张任务表单的控件显示和返回路径。
3. 不启动任何自动化任务；验证结束后停止 App 并返回系统桌面。

## 实施结果

- 结果：**改善**。B 端用户私信与评论区私信均移除了静态说明小字和重复页内标题；保留字段标签、输入/选择控件、必要校验和操作按钮。
- 输入控件改为带 1dp 描边的浅色圆角矩形；两页字段统一为 50dp 高、`bodyMedium` 文本。
- 评论入口/匹配选择改为 34dp 高的紧凑选择项；预设词条与操作按钮使用 8dp 圆角，保存/开始按钮为 46dp 高。
- 保留了所有原有字段、默认值、校验提示、保存、挂起和启动回调；没有修改任务模型、自动化执行、无障碍、抖音页面识别或网络请求。

## 验证结果

- `git diff --check` 通过。
- `./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug -PautomationApiEndpoint=<受管 HTTPS 服务地址>` 通过（55 个 Gradle 任务）；仅保留既有 Material/图标弃用警告。
- **真机 OnePlus NE2210 / b33aa309 / Android 16**：安装 Debug APK 后验证“首页 → B 端私信”；从页面左上角返回按钮回到首页，再进入“评论私信”。两页字段、预设/匹配选择、开关、校验显示和操作按钮均正常。测试中未保存、挂起或启动任务，未调用抖音；结束后已停止 App 并返回系统桌面。

## 几何与兼容性检查

- 全部新增/变更尺寸均为 Compose `dp`（50dp、46dp、34dp、8dp、1dp）；没有新增 px、自动化坐标、OCR 几何、图像匹配或设备相关手势时长。
- 新的选择项仍使用 Material `FilterChip` 语义；仅通过 Compose 最小交互尺寸组合项调整其视觉高度，未改变点击逻辑。
