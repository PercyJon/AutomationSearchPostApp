# 全局动作间隔配置化记录（2026-08-24）

## 修复前记录

- 当前错误现象：所有会改变目标应用状态的无障碍动作共享固定的 3,000ms 最小间隔，导致页面已就绪时仍出现明显空等。
- 稳定复现步骤：查看已完成任务 `designer-20260824-171744` 的诊断日志；同一用户操作收尾阶段连续记录了 `node_set_text wait_ms=1385`、`node_click wait_ms=2695`、`global_back wait_ms=1653`、`global_back wait_ms=1545`。
- 预期行为：操作员可在设置中留空以不启用全局动作节流；需要节流时只能填写 1,000–5,000ms，且已绑定的无障碍服务在下一次动作时使用新值。
- 实际行为：`AutomationActionPacer` 的默认参数固定为 3,000ms；设置页没有配置入口，不能持久化或在服务运行时调整。

## 本轮唯一根因假设

`AutomationActionPacer` 直接以固定默认值计算所有动作槽位，因而无论页面状态是否已确认，均会强制等待至 3,000ms。

## 最小修改范围与验证计划

- 新增纯输入校验与 SharedPreferences 设置存储；默认空值映射为 0ms。
- 将动作节流器改为在每个动作槽位读取该设置，不改动现有页面确认、OCR、重试次数或其他等待常量。
- 在“设置 → 自动化服务”增加输入框与显式保存；无效值不写入存储。
- 验证：单元测试覆盖留空、边界值、非法值、默认不节流及动态读取；执行 Debug 单测、Lint 与 APK 构建；再在真机验证设置默认值、边界校验和日志中的实际动作等待。

## 结果

- 改善：固定 3,000ms 默认节流已移除。空值映射为 0ms；填写的合法值会在每个新动作槽位读取，保存后不必重绑无障碍服务。
- 单元与构建：`./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug` 通过。
- 真机：OnePlus NE2210 / `b33aa309` / Android 16。安装 Debug 包后，设置页默认显示空值；`999` 显示范围错误且无法保存；`1000` 可保存并提示下一次动作生效；随后保存空值，界面显示“已关闭全局动作间隔”，私有偏好中的 `action_interval_millis` 为无内容字符串。
- 真机范围：无障碍服务保持启用；本轮只操作本项目设置页，未启动任务、未点击抖音、未输入或发送消息。
- 新增几何常量检查：未新增 Android 几何常量、固定 px、坐标或设备相关手势时长。
- dp 归一化检查：设置页复用既有 Compose `dp` 布局；新增逻辑仅为时间毫秒配置，不涉及 dp 或屏幕比例坐标。
