# M7-C2d：恢复阶段纯路由拆分

日期：2026-08-24
范围：`DouyinNavigationController.recoverAfterTimeout()` 的超时分流，不改变恢复动作。

## 变更前记录

- 现象：一个超时恢复方法同时包含阶段/页面判定、启动广告安全等待、重试、页面动作、跳过和暂停；分支等价性无法单独回归。
- 稳定复现步骤：分别让首页、搜索入口、搜索结果、用户结果或主页等待阶段触发既有看门狗超时，并提供对应页面类型或启动广告标记。
- 预期行为：保持现有有界恢复路径；首页启动广告只等待不点击，私信页超时保留既有失败归因，其余不支持的组合仍暂停。
- 实际差异：本轮为等价重构，没有线上故障；原分流与实际动作写在同一方法内，缺少纯函数测试。

## 单一假设与最小修改

假设：将“超时阶段 + 页面类型 + 启动广告可见性”抽为纯路由，可锁定恢复分流，而不会影响现有动作。

- 新增 `RecoveryFlowRouter`，覆盖搜索重试、首页归一化、用户结果续接、主页私信重试、失败跳过与暂停。
- 控制器继续从当前窗口读取页面及启动广告；广告标记存在时只延长有界等待并重新观察，从不点击广告控件。
- 控制器继续持有超时预算、延时、节点/OCR/几何/页面确认、全局返回、任务记录与暂停。

## 验证结果

- `RecoveryFlowRouterTest` 覆盖启动广告最高优先级，以及搜索、首页、用户结果、主页和不支持阶段的全部既有恢复出口。
- 自动化验证：`./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug` 与 `git diff --check` 通过。
- 真机 OnePlus NE2210（`b33aa309` / Android 16）：安装更新后无障碍服务为 Bound/Enabled、`Crashed services` 为空；本轮仅做停止态服务健康确认，不启动任务、不进行页面操作、空白探测或消息发送。

## 几何与安全检查

- 未新增 Android 几何尺寸、固定 px、坐标或手势；无需新增 dp 归一化逻辑。
- 启动广告仍只等待；节点优先、OCR 辅助、几何校验、页面确认和私信安全门保持不变。
