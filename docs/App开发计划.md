## 2. 总体目标

在**不破坏已有 B 端私信链路**的前提下，按以下优先级推进：

1. **P0 优先**：跑通一次「评论私信」真实、安全、有限闭环（不发送真实内容）。
2. **P1**：评论私信 5/10/20 条有界真机回归。
3. **P2**：评论筛选词、多视频、置顶跳过、当前主页模式。
4. **P3**：B 端私信稳定性回归（翻页、去重、名称、异常恢复）。
5. **P4**：后端远程任务、License、心跳、预设词接口完善。
6. **P5**：UI 产品化收尾、记录详情、统计、设置与发布准备。

同时把代码质量优化项（A/B/C/D/E）作为**横切任务**融入各里程碑，优先解决会直接影响「换机失效 / 重复骚扰用户 / 链路不可达」的 P0 级缺陷。

### M1 —— P0 评论私信真实闭环

**目的**：完成交接文档 §4 定义的唯一 P0 闭环：

```
抖音首页 → 搜索 designer → 用户标签 → 第一个用户 → 用户主页
→ 第一个视频 → 打开评论区 → 首条有效评论的头像 → 评论用户主页
→ 发私信 → 输入 ASCII 空格 → 发送 → 检测“不能发送空白消息”
→ 后退两层 → 回到原视频评论区 → 记录“模拟发送成功”
```

**前置评估（A5）**：

- [ ] 评估在 [`PageDetector.kt`](../app/src/main/java/com/example/douyinautomation/automation/PageDetector.kt) 增加 `VIDEO_SURFACE` / `COMMENT_SURFACE` 两个页面类型的必要性与成本。
- [ ] 若接入，则让 [`CommentEntryStateMachine.kt`](../app/src/main/java/com/example/douyinautomation/automation/CommentEntryStateMachine.kt) 对这两类页面做确定性分支，替代接受 `UNKNOWN`。

**执行闭环**：

- [ ] 按交接文档 §4.2 页面归一化规则启动。
- [ ] 严格按 §4.4 识别「首条有效评论」（左侧圆形头像 + 右侧灰名 + 黑正文 + 元信息同一行），只点头像。
- [ ] 按 §4.5 进入评论用户主页 → 私信入口（发私信/纸飞机，拒绝客服/购物车）→ 空格探测 → 检测空白提示。
- [ ] 后退两层验证仍回到原视频评论区。

**验收**：一次真实闭环成功，日志出现 `comment_task_started` 与空白提示检测记录；产物归档到 `artifacts/`。
