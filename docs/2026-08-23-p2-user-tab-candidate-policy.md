# 2026-08-23：P2-G1 用户标签安全资格策略抽取

本记录遵循项目根目录 `AGENTS.md` 的小步修改与同路径验证要求。

## 当前差异

- 现象：控制器在点击“用户”分类标签前，同时负责标签语义、可见性、分类栏边界和紧凑高度校验。
- 稳定复现：搜索结果页可能将“用户”文本暴露在大型内容容器中；该容器不是分类标签，点击可能离开安全搜索结果路径。
- 预期：只有精确用户标签、完整可见、位于上方分类栏且高度紧凑时才允许既有节点点击。
- 实际：安全资格规则嵌在控制器中，难以独立验证内容容器、裁切标签和真实标签三类边界。

## 本轮唯一根因假设

用户标签的纯安全资格判断与点击编排混合，降低了误触保护规则的可审计性。

## 最小修改与验证

- 新增 `UserTabCandidatePolicy`，逐字迁移原有语义、节点和屏幕比例判断；控制器保留选择、点击、横向揭示和后置确认流程。
- 不改变搜索输入、用户行选择、私信、评论、手势或坐标兜底。
- 风险：真实用户标签被错误拒绝，或内容容器被错误接受。
- 验证：精确可见标签、内容容器拒绝、裁切标签拒绝单测；完整 Debug 单测、Lint、构建；真机干跑。

## 验证结果

- 定向与完整检查：通过；`git diff --check` 无输出。
- 真机：OnePlus NE2210（Android 16 / SDK 36，设备序列号 `b33aa309`）；`designer`、匹配词“不错”、任一匹配、1 个视频 / 1 位用户、干跑。
- 关键路径：`user_tab_candidate` → `user_tab_opened [route=node_click]` → `user_tab_postcondition [page=USER_RESULTS]` → 用户结果身份 OCR → 评论候选干跑终态 `COMPLETED`。
- 安全与几何检查：未走横向滑动兜底，未进入评论用户主页、私信或空白消息探测；只复用屏幕比例，未新增固定 px、坐标点击或手势。
- 结果：改善。控制器降至 5,127 行，用户标签误触保护成为独立可测试的纯策略。
