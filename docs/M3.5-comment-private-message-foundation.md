# M3.5 评论私信基础层

本模块沿用现有节点优先、有限 OCR 和安全超时机制。评论任务与 B 端“搜索用户 → 主页 → 私信”执行路径隔离；所有发送验证均使用单个 ASCII 空格探测，不发送真实私信。

## 已落地

- 新增任务类型 `COMMENT_PRIVATE_MESSAGE`；旧任务默认仍为 `PROFILE_PRIVATE_MESSAGE`。
- 新增两种入口模式：搜索指定用户主页、使用当前已打开的用户主页。
- 新增评论匹配词配置，使用 `|` 分隔并采用“包含 + OR”匹配；未填写匹配词表示评论区全部用户参与。
- 新增视频数、每个视频用户数上限，配置会在任务启动时冻结到 `TaskSnapshot`。
- 新增评论任务阶段、进度计数和悬浮窗通用进度模型，为后续 WindowManager 悬浮窗复用。
- 本地任务草稿、任务检查点、历史记录均向后兼容：旧 JSON 没有新增字段时自动回退到原有 B 端私信任务。
- 增加 JVM 回归测试，覆盖关键词解析、空匹配全量命中、两种入口校验、快照冻结和旧任务默认行为。

## P3.5-A 已落地

- 新增评论候选提取器：节点文本优先，OCR 仅补充缺失文本；相同区域的 OCR 不会覆盖节点结果。
- 评论匹配结果保留评论文本、匹配词、作者文本、头像 bounds 和安全交互 bounds。
- 候选行必须符合“左侧圆形头像 + 右侧灰色作者名 + 下方评论内容”的结构；顶部定位卡片、评论数量、时间/回复、点赞/踩等操作描述不会进入候选。
- 进入用户主页严格点击重新定位后的评论头像，不点击名称、点赞/踩或其他邻近控件；纯 OCR 夹具没有头像节点时仅保留逻辑层回归，不授权真机冒险点击。
- 新增保守评论区检测器，要求评论标记结合底部评论输入或重复回复结构，避免视频页偶然出现“评论”字样就误进入评论流程。
- 已加入节点、OCR、空匹配、UI 噪声和评论区误判回归用例。

## P4-B Android 运行时已接入

- 评论任务在进入已确认用户主页后切换到独立 `CommentPrivateMessageRuntime`，不会落入原 B 端私信分支。
- 用户主页如果有多个内容标签，只有在“作品”未选中时才通过“作品”语义标签切换；只有一个“作品 N”标签时不点击标签，直接选择下方视频，避免弹出最新/最热菜单。没有作品、显示“暂无作品”或检测到“私密账号”时安全跳过当前用户并回到用户列表。第一个视频使用“作品/视频语义 + 图像节点 + 内容区结构”选取，实时重新解析节点后点击。
- 任务配置提供“跳过置顶视频”开关；开启后按“置顶”语义标记排除置顶卡片，选择可见的最新普通作品，避免把置顶内容当作目标视频。
- 视频右侧评论按钮使用语义节点优先；缺少语义时才按右侧操作栏结构选择第二个按钮（点赞、评论、收藏/转发顺序），不直接点击 OCR 文本。
- 评论面板通过评论标题/回复标记和底部输入框等组合信号确认；随后读取当前视口、按作者身份去重，并以归一化手势或可滚动节点继续加载。
- 识别“暂时没有更多了”等终止标记后结束本视频读取；无评论时要求同时识别“期待你的评论”和“去评论”按钮，作者“发布了作品”系统行不会计为评论用户。视频/评论动作每一步有 12 秒 watchdog，搜索入口有 60 秒总入口保护，评论分页最多滚动 20 次，风险/登录页面仍转人工接管，不会为寻找末尾评论无限滚动。

## P4-C 评论用户私信探测已接入

- 评论匹配候选按稳定身份键去重；每个候选先用头像 hierarchy path/邻近几何重新定位，再点击头像进入主页。名称、定位、点赞/踩等文本或 contentDescription 不作为点击目标；头像无法重新定位时跳过当前候选并记录单用户失败。
- 头像 dispatch 前再对当前活节点做一次末端校验：资源 ID/类名/头像语义、近方形尺寸、位于作者列左侧、与候选行和原头像 bounds 对齐必须同时满足；页面重绘后路径若指向评论文字、回复或其他控件，会拒绝点击并跳过该候选。
- 评论内容读取只消费可见 `node.text`，不把 ImageView 的 contentDescription 当作评论/账号文本；评论数只在弹窗顶部中心区域作为内容边界，避免“赞0，未选中”“踩，已选中”“8076人打卡”等控件或定位信息污染名称。
- 进入主页后只接受带有“发私信/私信”等语义且不含“客服、咨询、购物车、商品”等风险词的可点击入口；不对 OCR 文本直接点击，避免误入客服或购物车页面。
- 私信页、权限限制、空消息拒绝和发送失败均通过 PageDetector 轮询确认；每一步有 12 秒上限，空消息探测 8 秒上限。
- 探测只在输入框写入一个 ASCII 空格并提交，预期抖音显示“不能发送空白消息”；不会发送用户真实文案。探测结果写入用户处理记录，随后按“私信页 → 用户主页 → 视频评论面板”顺序执行有限返回；未确认回到评论面板前不会处理下一个候选。
- 评论用户处理失败默认按单用户失败跳过；验证码、登录、风控或无法在限定次数内返回评论面板才暂停/结束任务。评论分页仍限制为最多 20 次，不尝试无界滚动到底。
- 多视频任务在单个视频达到“评论到底”或用户上限后，会先关闭评论面板，再从已确认的视频页面执行一次有限上划切换；评论用户使用任务级稳定身份去重，避免下一视频重复探测同一用户。单视频任务保持原有结束行为。
- 当前已完成 JVM 编译、单元测试、Lint 和 APK 构建；尚未在真实评论面板上执行有界 10/20 条候选的真机闭环，因此不宣称 P4-C 真机验收完成。

## P3.5-B 悬浮窗已接入

- 新增 `FloatingTaskProgressStore`，提供开始、暂停、继续、停止、完成、清空和计数更新。
- 状态只包含任务标识、计数和阶段文案，不保存评论、OCR 或账号原文，可直接作为后续 `WindowManager` 悬浮窗的数据源。
- 新增 `FloatingOverlayService`，使用 `TYPE_APPLICATION_OVERLAY` 显示紧凑进度卡片：任务名/阶段、处理进度、成功/失败/总数，以及暂停/继续/停止控制。
- 进度卡片右上角提供“收起”；收起后变为贴近屏幕右侧的圆角小方块，点击方块可恢复完整卡片，收起/展开不会改变任务状态。
- 悬浮窗为可选能力：设置页可打开 Android“在其他应用上层显示”权限；未授权时任务仍照常执行，不会阻塞 B 端或评论私信流程。
- 任务开始时自动尝试显示悬浮窗；暂停时保留悬浮窗以便继续，完成/失败/停止时自动移除。标题区域支持拖动，便于避开抖音控件和系统提示。
- 悬浮窗只展示进度和生命周期控制，不显示评论、OCR、账号名称或真实消息内容；当前使用普通 Service 启动，不引入额外通知渠道。
- 自动化任务启动时悬浮窗默认以贴边小方块显示，避免展开面板遮挡抖音底层点击；需要查看进度时点击小方块展开，开始新任务会再次自动收起。

## P4-A 状态机与安全信号已落地

- 新增“用户主页 → 第一个视频 → 评论区”的纯逻辑状态机，只有确认上一页面后才会发出下一步动作。
- 第一个视频入口采用“作品/视频语义标记 + 可点击图像节点 + 内容区结构”组合确认，不点击头像、不写死坐标。
- 评论入口优先选择右侧操作栏的语义“评论”节点；没有语义文本时，要求右侧操作栏至少有三个按纵向排列的图像按钮，再取第二个作为聊天气泡候选，不直接点击 OCR 文字。
- 直播内容单独识别：出现“点击进入直播间/进入直播”等入口提示时只执行有限上划，不点击直播卡片；若误进入直播间，则要求上方关闭控件与右下分享/转发控件形成组合信号，优先点击语义化关闭节点，找不到节点时使用系统返回，再回到直播卡片上划。直播状态不进入评论或私信流程。
- 评论面板必须通过现有保守评论区检测器确认后才进入读取阶段；滚动到底后识别“暂时没有更多了/暂无更多”等终止标记。
- 评论行按“作者名称在上、评论内容在下、左侧列对齐”配对，降低把顶部按钮或视频文案当成用户名称的概率。
- 登录、验证码、风控、未知页面和超时均停止自动点击；风险页面转入人工接管状态。
- 评论任务动作已接入现有控制器的独立分支；B 端旧任务仍保持原有搜索/私信逻辑，不会误走评论运行时。

## 下一步顺序

## 当前 P0 回归合同（开发测试固定项）

为避免开发测试反复录入表单，Debug APK 的评论私信入口固定使用以下有界合同：

- 搜索用户：`designer`；
- 视频数：`1`；
- 每个视频只处理首条有效评论；
- 不设置评论匹配词；
- 只提交一个 ASCII 空格做空消息安全探测，不发送真实私信；
- 评论候选必须从评论区顶部第一条完整评论开始，忽略定位卡片、评论总数、系统作者行、时间/回复/点赞/踩等控件；
- 进入用户主页只点击经过头像几何校验的圆形头像，完成“头像 → 主页 → 纸飞机私信 → 空格探测 → 返回两层 → 评论区”的闭环。

每次启动 P0 回归前，控制器先把抖音归一化到首页：如果抖音恢复在用户主页、视频页、评论页、搜索页或结果页，统一使用有限次数的系统返回；只有确认首页后才打开搜索并提交 `designer`。如果短时间内没有可读的无障碍页面树，也会执行有限次数的盲返回并重新观察，超出上限则记录为任务失败，不进入无限等待。该合同只用于 Debug 回归，不改变正式版本的可配置表单。

### P0 启动可靠性补充

- UI 现在区分“系统设置已启用无障碍”与“无障碍服务已安装命令接收器”；调试 Intent 只会在后者成立后下发 P0，避免 Compose 与服务绑定同时发生时丢失一次性启动命令。
- 无障碍服务先同步订阅命令流，再公布可执行状态；若服务短暂重连，任务入口会等待接收器恢复，而不会把启动命令静默写入没有订阅者的流。
- 启动观察没有可读节点树时，会进入最多 4 次的盲返回恢复；每次返回后重新读取目标窗口。仍无法取得树或回到首页时，记录任务失败并回到记录页，不无限重试。
- 对自定义渲染的视频页，经安全校验的右侧评论操作栏本身可作为视频页确认；不再额外依赖“播放/视频”文本或全宽节点。视频页确认保持 18 秒有界等待，其余常规步骤仍为 12 秒；重置步骤看门狗时会使旧计时器失效，避免页面刚确认时旧超时任务抢先终止流程。
