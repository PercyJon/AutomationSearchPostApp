# M3.5 评论私信基础层

本模块沿用现有节点优先、有限 OCR 和安全超时机制。评论任务与 B 端“搜索用户 → 主页 → 私信”执行路径隔离；所有发送验证均使用单个 ASCII 空格探测，不发送真实私信。

## 已落地

- 新增任务类型 `COMMENT_PRIVATE_MESSAGE`；旧任务默认仍为 `PROFILE_PRIVATE_MESSAGE`。
- 新增两种入口模式：搜索指定用户主页、使用当前已打开的用户主页。
- 新增评论匹配词配置，使用 `|` 分隔并采用“包含 + OR”匹配；未填写匹配词表示评论区全部用户参与。
- 新增视频数、每个视频用户数上限，配置会在任务启动时冻结到 `TaskSnapshot`。
- 新增评论任务阶段、进度计数和悬浮窗通用进度模型，为后续 WindowManager 悬浮窗复用。
- 本地任务草稿、任务检查点、历史记录均向后兼容：旧 JSON 没有新增字段时自动回退到原有 B 端私信任务。
- 增加 JVM 回归测试，覆盖关键词解析、空匹配全量命中、两种入口校验、快照冻结和旧任务默认行为。

## P3.5-A 已落地

- 新增评论候选提取器：节点文本优先，OCR 仅补充缺失文本；相同区域的 OCR 不会覆盖节点结果。
- 评论匹配结果保留评论文本、匹配词、作者文本、作者 bounds 和安全交互 bounds。
- 作者点击区域优先使用作者名称文本，不使用头像区域；缺少作者节点时才保留评论区域作为待验证兜底。
- 新增保守评论区检测器，要求评论标记结合底部评论输入或重复回复结构，避免视频页偶然出现“评论”字样就误进入评论流程。
- 已加入节点、OCR、空匹配、UI 噪声和评论区误判回归用例。

## P4-B Android 运行时已接入

- 评论任务在进入已确认用户主页后切换到独立 `CommentPrivateMessageRuntime`，不会落入原 B 端私信分支。
- 第一个视频使用“作品/视频语义 + 可点击图像节点 + 内容区结构”选取，实时重新解析节点后点击。
- 视频右侧评论按钮使用语义节点优先；缺少语义时才按右侧操作栏结构选择第二个按钮（点赞、评论、收藏/转发顺序），不直接点击 OCR 文本。
- 评论面板通过评论标题/回复标记和底部输入框等组合信号确认；随后读取当前视口、按作者身份去重，并以归一化手势或可滚动节点继续加载。
- 识别“暂时没有更多了”等终止标记后结束本视频读取；无评论时要求同时识别“期待你的评论”和“去评论”按钮，作者“发布了作品”系统行不会计为评论用户。视频/评论动作每一步有 12 秒 watchdog，搜索入口有 60 秒总入口保护，评论分页最多滚动 20 次，风险/登录页面仍转人工接管，不会为寻找末尾评论无限滚动。

## P4-C 评论用户私信探测已接入

- 评论匹配候选按稳定身份键去重；每个候选优先点击作者名称节点，不点击头像。节点不可重新定位时仅使用同一作者节点的 hierarchy path，无法确认作者名称则跳过并记录失败。
- 进入主页后只接受带有“发私信/私信”等语义且不含“客服、咨询、购物车、商品”等风险词的可点击入口；不对 OCR 文本直接点击，避免误入客服或购物车页面。
- 私信页、权限限制、空消息拒绝和发送失败均通过 PageDetector 轮询确认；每一步有 12 秒上限，空消息探测 8 秒上限。
- 探测只在输入框写入一个 ASCII 空格并提交，预期抖音显示“不能发送空白消息”；不会发送用户真实文案。探测结果写入用户处理记录，随后最多返回评论面板并继续下一个候选。
- 评论用户处理失败默认按单用户失败跳过；验证码、登录、风控或无法在限定次数内返回评论面板才暂停/结束任务。评论分页仍限制为最多 20 次，不尝试无界滚动到底。
- 当前已完成 JVM 编译、单元测试、Lint 和 APK 构建；尚未在真实评论面板上执行有界 10/20 条候选的真机闭环，因此不宣称 P4-C 真机验收完成。

## P3.5-B 悬浮窗已接入

- 新增 `FloatingTaskProgressStore`，提供开始、暂停、继续、停止、完成、清空和计数更新。
- 状态只包含任务标识、计数和阶段文案，不保存评论、OCR 或账号原文，可直接作为后续 `WindowManager` 悬浮窗的数据源。
- 新增 `FloatingOverlayService`，使用 `TYPE_APPLICATION_OVERLAY` 显示紧凑进度卡片：任务名/阶段、处理进度、成功/失败/总数，以及暂停/继续/停止控制。
- 悬浮窗为可选能力：设置页可打开 Android“在其他应用上层显示”权限；未授权时任务仍照常执行，不会阻塞 B 端或评论私信流程。
- 任务开始时自动尝试显示悬浮窗；暂停时保留悬浮窗以便继续，完成/失败/停止时自动移除。标题区域支持拖动，便于避开抖音控件和系统提示。
- 悬浮窗只展示进度和生命周期控制，不显示评论、OCR、账号名称或真实消息内容；当前使用普通 Service 启动，不引入额外通知渠道。

## P4-A 状态机与安全信号已落地

- 新增“用户主页 → 第一个视频 → 评论区”的纯逻辑状态机，只有确认上一页面后才会发出下一步动作。
- 第一个视频入口采用“作品/视频语义标记 + 可点击图像节点 + 内容区结构”组合确认，不点击头像、不写死坐标。
- 评论入口优先选择右侧操作栏的语义“评论”节点；没有语义文本时，要求右侧操作栏至少有三个按纵向排列的图像按钮，再取第二个作为聊天气泡候选，不直接点击 OCR 文字。
- 评论面板必须通过现有保守评论区检测器确认后才进入读取阶段；滚动到底后识别“暂时没有更多了/暂无更多”等终止标记。
- 评论行按“作者名称在上、评论内容在下、左侧列对齐”配对，降低把顶部按钮或视频文案当成用户名称的概率。
- 登录、验证码、风控、未知页面和超时均停止自动点击；风险页面转入人工接管状态。
- 本轮仍未把动作接入现有 B 端控制器，避免评论任务误走 B 端搜索流程。
