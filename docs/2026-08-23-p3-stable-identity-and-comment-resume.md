# 2026-08-23：P3 稳定身份去重与评论恢复回归

本记录遵循项目根目录 `AGENTS.md` 的小步修改、单一根因假设与同路径验证要求。

## P3-A：搜索用户身份碰撞

- 现象：搜索用户去重、检查点和任务记录关联使用 32 位字符串哈希。
- 稳定复现：不同文本可产生相同的 32 位哈希；例如测试中的两个不同键具有相同旧哈希值。
- 预期：不同稳定身份绝不因哈希碰撞被合并；任务重启后仍能跳过同一用户。
- 实际：碰撞理论上可让不同用户被误判为已处理，或将记录更新关联到错误用户。

唯一根因假设：用 32 位哈希作为身份等值判断，无法满足去重键的唯一性要求。

最小修改：新增 `UserIdentityFingerprint`，使用稳定键规范化后的 SHA-256；搜索用户、评论用户、检查点、任务记录关联和远程记录缓存均改用指纹。旧检查点和历史任务记录保留只读兼容字段；旧检查点因不包含原始稳定键，恢复时只能沿用旧比较，新写入检查点一律使用 SHA-256。

## P3-B：评论候选进程重启后重复

- 现象：评论任务级候选去重只存在运行时内存中。
- 稳定复现：处理一位评论候选后重启进程并恢复同一任务，再次遇到该候选。
- 预期：已尝试候选在恢复后仍被跳过，且不保存评论正文或原始身份文本。
- 实际：旧实现会重新创建空的任务级集合，无法识别该候选已被处理。

唯一根因假设：任务检查点没有保存评论候选的最小去重证据。

最小修改：新增 `CommentCandidateResumeLedger`，只保存候选稳定键的 SHA-256 指纹；首次将候选放入执行队列时同步写入活跃任务检查点，恢复运行时重新装载。头像确认、页面确认、私信入口判定、空白探测、返回评论区和手势均未改动。

## P3-C：当前主页评论任务的空查询检查点

- 现象：当前主页评论任务合法地不含搜索词，而旧检查点读写假定查询列表非空。
- 稳定复现：当前主页评论任务首次持久化已处理评论候选。
- 预期：以逻辑索引 `0` 保存并可恢复该任务。
- 实际：旧路径会对空查询列表计算索引范围，可能拒绝或中断检查点处理。

唯一根因假设：查询索引归一化没有区分“搜索任务”和“当前主页评论任务”。

最小修改：新增 `TaskCheckpointQueryIndexPolicy`，在检查点读写两端统一处理：有搜索词时校验索引；当前主页评论任务无搜索词时固定为 `0`；其他空查询任务仍拒绝。

## 风险与验证

- 影响范围：仅身份去重、检查点、任务记录关联与评论候选恢复；未修改搜索、主页跳转、私信入口、消息输入、发送或手势链路。
- 风险：旧检查点没有原始身份键，无法无损转换为 SHA-256；因此仅在恢复旧检查点时保留旧比较，新任务不再写入旧格式。
- 单测：覆盖相同旧哈希的不同身份不再合并、旧检查点兼容匹配、评论候选跨实例恢复、空搜索词当前主页检查点，以及既有名称解析、受限页面与发送失败检测用例。
- 完整检查：`./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug` 通过；`git diff --check` 无输出。
- 真机：OnePlus NE2210（Android 16 / SDK 36，设备序列号 `b33aa309`）；搜索 `designer`、匹配词“不错”、任一匹配、1 个视频 / 1 位用户、干跑。
- 真机路径：语义搜索 → 用户标签 → 结构行 + OCR 身份识别（记录 SHA-256 前缀）→ 用户主页 → 首条视频 → 评论面板 → 首位安全候选确认 → `COMPLETED`。未点击评论候选头像、未进入评论用户主页、私信或发送步骤。

## 当前限制

本次受控真机路径是“搜索目标主页”的单用户评论干跑，已覆盖新的搜索身份指纹和完整安全导航链路；它不等同于普通 B 端多页用户列表的实时分页数据集。普通 B 端的翻页、名称、受限和发送失败分支继续由既有静态回归覆盖；取得可验证的多页实时结果数据后，应补做不发送真实内容的真机翻页回归。
