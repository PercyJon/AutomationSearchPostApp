# M6-B3：节点观察事件增量签名

## 问题记录

- 当前错误现象：每个无障碍事件都会把整棵节点树拼接为一个临时字符串后再计算 `hashCode()`；节点数较多且 `TYPE_WINDOW_CONTENT_CHANGED` 高频到达时，会反复分配大字符串。
- 稳定复现：保持页面结构不变，在抖音前台产生连续内容变化事件；旧路径会按每次事件遍历全部节点并构造完整拼接字符串。
- 当前预期行为：继续使用相同节点语义与几何字段、相同节点顺序参与去重，但避免构造整棵节点树的中间字符串。
- 实际行为差异：去重结果虽可用，事件风暴下却存在不必要的字符串分配和 GC 压力。

## 单一根因与最小修改

唯一根因假设：旧签名在哈希前先构造整树文本，是高频观察路径中可避免的主要分配来源。

- 新增 `NodeObservationSignaturePolicy`，按原遍历顺序逐节点混入原有字段：`text`、`contentDescription`、边界四边、`isSelected`、`isVisibleToUser`。
- `DouyinAccessibilityService` 只替换节点签名的一行调用；页面检测、OCR 签名、最终去重条件、控制器调度及所有动作安全门均保持不变。
- 签名仍只保留在内存中参与去重；本轮不新增节点文本、搜索词、账号或消息内容日志。

## 验证

- `NodeObservationSignaturePolicyTest`：通过。覆盖相同快照结果一致、每个既有语义/几何字段变化、节点顺序变化。
- `./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug`：通过。
- `git diff --check`：通过。

## 真机验证

- 设备：OnePlus NE2210，Android 16，序列号 `b33aa309`。
- 路径：安装 Debug APK → 保持本地任务停止 → 回到系统桌面 → 仅将抖音带到前台以触发观察事件 → 检查无障碍服务状态与应用日志。
- 结果：改善。服务为 Bound/Enabled，Crashed 为空；未出现 `node_inspection_failed`。抖音用户主页前台观察正常。
- 安全结果：未启动或恢复任务，日志未出现任务批次、空白消息探测或消息发送；未执行页面内点击、滑动或私信动作。

## 风险与边界

- 风险：增量混合函数与字符串 `hashCode()` 的碰撞分布不同，但签名只是一层内容变化去重，并不作为节点点击或页面识别的依据；字段覆盖和顺序已由单测固定。
- 本轮不改变截图、OCR、节点优先、几何校验、页面确认、归一化坐标或私信安全策略。

## 几何与 dp 归一化检查

- 未新增或修改 Android 几何尺寸、固定 px、坐标比例、点击或手势。
- 节点边界仅延续既有签名字段，不参与新增几何阈值判断；无需新增 dp 归一化逻辑。
