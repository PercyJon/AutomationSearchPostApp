# 2026-08-25：换视频未确认导致同一条视频重复处理

## 修复前记录

- **错误现象 1**：任务 `室内设计师-20260825-175318`（3 视频 × 每视频 2 评论）日志自称完成 3 个视频、6 次空白探测，实际 6 条私信都在同一条视频的评论用户上，没有真正换片。
- **错误现象 2**：任务 `室内设计师-20260825-175914` 第一条视频发 2 人后换到第二条正常；第二条发了 4 人。
- **稳定复现步骤**：OnePlus NE2210（Android 16 / `b33aa309`），「室内设计师 / 3 视频 / 每视频 2 评论」。
- **预期行为**：每条视频最多处理 2 个评论用户；处理满后关闭评论区、上滑到下一条作品，再打开该作品的评论区。
- **实际行为差异**：`advanceAfterVideo` 在返回评论区之后无条件再 BACK 一次，只等 120ms 就上滑；页面指纹只要变化就把 `videoIndex` 加一并清空本视频人数。评论列表滚动也会让指纹变化，因此同一条视频会被当成新视频继续处理。

## 本轮唯一根因假设

换视频动作没有证明「评论面板已关、当前是播放器、滑完是新作品」，却提前清空了每视频人数上限。

## 最小修改

1. 只有 `CommentSurfaceDetector` 确认评论区还开着，才 BACK 关面板，并用有界轮询等到关掉。已经在视频上则不再 BACK。
2. 只在面板已关的播放器上取滑动前指纹；不再用 `RETURN_TO_COMMENT_DELAY_MS` 作为关面板等待。
3. 滑完必须面板仍关、指纹与滑动前不同、且仍是视频面，才增加 `videoIndex`、清空本视频人数、打开新评论区。事件路径在确认前不会 `OPEN_COMMENTS`。
4. 若面板仍开或关面板后指纹未变，最多再滑一次；仍未确认则失败停止，不在同一条视频上继续点人。

## 第 2 轮最小修改（首屏行位置 + 轻甩）

本轮唯一根因假设：整树指纹在同一条视频上也会变，在相邻作品上又可能不变；后者会触发再滑一次并跳过中间视频。长距离慢拖也不像换片轻甩。

1. 滑完面板关闭且有评论入口即打开评论区，不要求指纹变化。
2. 首屏行比例接近第一条视频的基线才 `commit` 并处理；续翻（如 `1377/2412`）视为同一条，关面板后再滑一次，不处理更多人。
3. 只有评论面板仍打开，探针才允许因面板未关而重滑。
4. 换片手势改为 `y 0.70→0.42`、180ms。

## 第 1 轮验证结果

- JVM：`NextVideoAdvancePolicyTest`、`NextVideoTransitionProbePolicyTest`、`TuningConstantsTest`。
- 真机 OnePlus NE2210 / `b33aa309` / Android 16，同一条件「室内设计师 / 3 视频 / 每视频 2 评论 / 跳过置顶开启」，空白探测。
  - 关面板：确认 `open=true` 才 BACK，随后 `open=false` 再取指纹并上滑。
  - 第一条 `row_tops=1067,1318`，2 人探测成功。
  - 第一次上滑 `comment_next_video_confirmed video_index=1`，但下一次队列是 `row_tops=1377,1713`（与修复前同一列表续翻一致），不是新视频首屏。
  - 第二条满 2 人后再次上滑：`changed=false`，重滑一次仍未确认，任务失败停止，没有继续点第 5、6 人。
  - 本轮结果：**部分改善**。

## 几何与安全检查

- 几何：行位置用屏幕高度比例 `0.52` / 基线 `+0.08`，不是 px。手势 `0.70→0.42`。
- 关面板仍是全局 BACK，且仅在确认评论区打开时发出。
- 空白探测仍只提交一个 ASCII 空格。
