# M7-C1：跨流程调参收敛完成

## 问题记录

- 当前错误现象：自动化运行所依赖的跨流程时序、轮询、重试、恢复、滚动上限、消息安全探测和归一化手势参数分散在导航控制器、评论运行时和无障碍服务中。
- 稳定复现：审阅一次从启动到搜索、用户选择、私信空白探测、评论多视频切换或服务重连的有界预算时，需要跨三个大类文件查找来源，难以确认关联上限是否同步。
- 当前预期行为：影响跨流程运行节奏的参数应当集中命名、注释和版本化；迁移不能改变任何默认值、安全停止条件或动作顺序。
- 实际行为差异：功能虽已稳定，但配置来源分散，后续维护存在遗漏相关限制或无意放宽安全预算的风险。

## 单一根因与最小修改

唯一根因假设：跨流程运营参数没有统一、代码拥有的来源，造成安全审阅和维护边界不清。

- 新增版本化 `TuningConstants`，以 `NavigationLifecycle`、`NavigationFlow`、`CommentRuntime`、`AccessibilityLifecycle` 四个只读分组收敛跨流程运行参数。
- 保留所有既有数值：启动/阶段超时、OCR 节流、检查点恢复、用户结果后置确认、私信入口和空白探测、评论滚动/直播停止上限、评论视频切换，以及归一化手势参数。
- 配置层仍只由应用代码拥有；不接入远程下发，也不允许通过配置放宽节点、OCR、几何、页面确认或消息安全门。

## 有意保留在所属模块的常量

- 加密算法、系统/存储键、协议/枚举状态、文件格式限制：它们不是运行调参，集中到自动化调参层会混淆安全边界。
- 单一检测器内部的数学证据系数和比例：它们与对应的节点/OCR/几何证明不可分离，继续由模块私有测试约束；不是可跨流程复用或远程调整的参数。
- 上述保留不代表允许新增固定 px。新增或修改 Android 几何尺寸仍必须遵守 dp 或屏幕比例规则。

## 验证

- `TuningConstantsTest`：通过。锁定启动、评论私信、评论滚动、直播、恢复、消息安全与归一化手势的关键既有上限。
- 配置引用审计：控制器 84 个 `NavigationFlow` 引用均在统一层有对应声明；控制器、评论运行时和无障碍服务不再保留跨流程运营 `const val`。
- `./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug`：通过。
- `git diff --check`：通过。

## 真机验证

- 设备：OnePlus NE2210，Android 16，序列号 `b33aa309`。
- 路径：安装 Debug APK → 保持本地任务停止 → 检查无障碍服务绑定状态与诊断日志。
- 结果：改善。服务为 Bound/Enabled，Crashed 为空；日志记录服务连接、刷新率手势配置和 OCR 初始化成功。
- 安全结果：未启动或恢复任务，未执行页面点击、滑动、空白消息探测或消息发送。

## 几何与 dp 归一化检查

- 未新增或修改 Android 几何尺寸、固定 px、点击坐标或动作逻辑。
- 迁移的用户页滑动与搜索提交区域继续使用 `0..1` 归一化比例；它们与 dp 尺寸体系严格分离。
