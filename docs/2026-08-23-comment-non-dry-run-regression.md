# 2026-08-23：评论私信非干跑空消息安全闭环回归

本记录遵循项目根目录 `AGENTS.md` 的小步修改与同路径验证要求。干跑仅验证识别，不可替代真实场景中的空消息安全闭环。

## 当前差异

- 现象：带匹配词的评论任务能够得到候选统计，但在首行结构校验处结束，尚未在当前真实页面完成“评论用户主页 → 私信页 → 空消息提交 → 平台拒绝确认 → 返回评论区”的非干跑验证。
- 稳定复现：使用搜索词 `designer`、匹配词“不错”、全部匹配、1 个视频 / 1 位用户；先前干跑记录显示首个头像顶部为 1139、首个候选顶部为 1386，并以“首条评论信息不完整”结束。
- 预期：非干跑模式中，只有头像、作者/正文和页面状态形成可验证同一评论行时，才进入该用户主页并执行空消息安全探测；任一环节不可确认时停止，绝不发送真实内容。
- 实际：私有节点诊断显示首行已有头像、标题和正文节点，但该行不含匹配词；首个命中候选从下一行开始。运行时把“首个命中候选”错误要求为首个可见评论行，导致本次真实场景回归未抵达私信页。

## 本轮唯一根因假设

首行安全门把“首个可见评论行”与“首个包含匹配词的评论行”混为一谈；当完整的首行不匹配而下一行匹配时，安全门会误判为首行不完整。

## 最小修改与验证

- 已以 `dryRun=false` 运行相同配置，保存私有诊断并确认基线。
- 仅在首行安全门中增加“首行已完整且不匹配”的例外；仍要求首行的头像、标题和正文由无障碍节点在同一行内确认，不滚动、不降低候选头像校验。
- 风险：错误地把不完整首行认作完整行，可能误入无关主页。
- 验证：单测覆盖“完整但不匹配的首行允许下一命中行”和“不完整首行仍停止”；完整 Debug 单测、Lint、构建；同一真机以非干跑方式验证空消息被平台拒绝且未发送真实内容。
