# M3-H 远程任务断点续跑

## 目标

远程任务在 App 进程重启、无障碍服务重新绑定或操作员重新领取后，不从用户结果首屏重新处理，而是根据后台记录的最后用户锚点继续。

## 实现

- 领取远程任务后，客户端先请求 `claim` 和 `progress`，使用同一次启动流程中的权威结果。
- `processed_count == 0` 时从首个稳定用户行开始。
- `processed_count > 0` 且存在 `last_user_key` 时，先打开用户结果页，按节点身份优先、OCR 兜底的顺序逐页查找锚点；锚点所在行之后才允许选择用户。
- 锚点所在页尚未加载完成时等待；锚点不在当前视口时才执行下一次有界滚动，避免把半屏旧数据误判成新页。
- 锚点超过限定页数仍未找到、系统覆盖层持续遮挡、页面进入登录/风控/验证码等未知状态时暂停并等待人工处理。
- `last_user_key` 不写入本地任务检查点；重新领取时始终从后端重新读取，避免本地过期或隐私数据导致错误续跑。

## 安全边界

本阶段仍只执行 M2 空白消息安全探测，不发送远程任务中的真实文案。断点定位失败时宁可暂停，也不会猜测行号或使用固定坐标继续。

## 验证

- `RemoteTaskResumePolicyTest` 覆盖新任务、缺失锚点和有效锚点三种情况。
- Android JVM 单元测试、Lint、Debug APK 和 instrumentation APK 构建通过。
