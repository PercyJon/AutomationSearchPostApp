# M7-C2f：搜索阶段动作编排拆分

日期：2026-08-24
范围：搜索阶段页面观察后的既有打开搜索、恢复、输入、复用结果、用户标签和候选选择分派。

## 变更前记录

- 现象：搜索纯路由已独立，但控制器页面观察主干仍直接执行其六种搜索阶段动作。
- 稳定复现步骤：向首页、搜索入口、搜索结果或用户结果等待阶段提供对应的既有页面类型。
- 预期行为：每种已存在的搜索路由只能触发原有一个搜索动作；无关页面不应被搜索阶段消费。
- 实际差异：本轮为等价重构，没有线上故障；原动作分派无法在无障碍服务之外独立验证。

## 单一假设与最小修改

假设：将搜索路由的动作分派移入 `SearchFlow`，由控制器提供原有方法回调，可保持节点/OCR/几何/手势实现不变并获得独立测试。

- 新增 `SearchFlow`，仅消费 `SearchFlowRouter` 已确认的路由。
- 控制器仍独占实际搜索、恢复、关键词输入、用户标签/候选选择、节点/OCR/几何验证和手势。
- 回调继续使用触发页面观察的同一已确认上下文。

## 验证结果

- `SearchFlowTest` 覆盖六种既有搜索动作与无关页面不消费。
- 自动化验证：`./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug` 与 `git diff --check` 通过。
- 真机 OnePlus NE2210（`b33aa309` / Android 16）：安装更新后无障碍服务为 Bound/Enabled、`Crashed services` 为空；本轮仅做停止态服务健康确认，不启动任务、不进行页面操作、空白探测或消息发送。

## 几何与安全检查

- 未新增 Android 几何尺寸、固定 px、坐标或手势；无需新增 dp 归一化逻辑。
- 搜索、用户标签和候选选择继续遵守节点优先、OCR 辅助、几何校验和页面确认顺序。
