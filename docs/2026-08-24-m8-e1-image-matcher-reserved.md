# 2026-08-24：M8-E1 ImageMatcher 预留通道边界

本记录遵循项目根目录 `AGENTS.md` 的安全、真机验证和 dp 归一化要求。

## 当前状态确认

- `NoOpImageMatcher` 是当前唯一启用实现，恒定返回 `null`，不保留截图数据。
- 代码审计确认 `ImageMatcher`、`NoOpImageMatcher` 与 `VerifiedTemplateMatcher` 没有被控制器、评论运行器、选择器或手势引擎注入/调用。
- 因此图像匹配不会触发页面跳转、点击、手势、消息输入/发送，也不会绕过节点、OCR、几何或页面确认。

## 发布边界

- 本阶段明确将图像匹配定为**禁用的预留诊断通道**，不接入 OpenCV，不下发模板，不持久化截图，不提供开关来替代现有动作链路。
- 不得用于验证码、风控页、登录验证或人工接管页面；风险/人工接管始终优先暂停。

## 后续启用的强制前置条件

1. 取得并脱敏审核每种目标页面的模板来源与生命周期；模板只可用于已确认页面中的辅助验证。
2. 采用多尺度 + ORB 特征匹配；所有模板区域、尺寸阈值以 `dp × density` 或可用屏幕比例表达，禁止固定 px。
3. 匹配结果必须同时满足既有无障碍节点、几何和页面状态确认；不能把 `ImageMatch.bounds` 直接转换为点击坐标。
4. 以至少两种分辨率真机完成搜索、主页、评论、私信及风险页回归，并记录误匹配率、耗时和未匹配安全降级结果。
5. 新实现、模板资产、依赖和启用开关须作为独立变更提交；未满足以上条件时继续使用 `NoOpImageMatcher`。

## 验证结果

- 静态审计：`rg` 确认没有 `ImageMatcher` 的运行时注入或动作调用点；`NoOpImageMatcher` 仍为唯一实现选择。
- 完整检查：沿用本轮 `./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug` 成功结果；本阶段未改变可执行逻辑。
- 真机：不需要为未启用的预留接口启动自动化任务；C4 安装回归已确认 OnePlus NE2210 可启动应用且未启动无障碍服务或任务。
- 几何检查：没有新增 Android 几何尺寸、固定 px、坐标或手势时长；无需新增 dp 归一化项。
