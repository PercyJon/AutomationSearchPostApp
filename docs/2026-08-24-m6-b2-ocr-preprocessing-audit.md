# M6-B2：OCR 裁剪与放大审计

## 审计结论

本项在当前代码中已经完成，不重复修改稳定 OCR 链路。

- 实现提交：`7614f38`（2026-08-18）。
- `MlKitOcrEngine.recognize()` 的实际顺序为：按 `OcrRegion` 计算裁剪框 → 创建区域位图 → 仅当裁剪后的任一边小于 720 时才放大 1.5× → 识别 → 将 OCR 边界映射回完整截图坐标。
- 全屏 `FULL` 的 1080×2412 输入两边均大于 720，因此不会被 1.5× 放大；满足“避免全屏 1.5×”要求。

## 调用覆盖与边界

- 自动化用户结果、主页头部、主页操作区、消息输入区和 Toast 分别使用 `USER_RESULTS`、`PROFILE_HEADER`、`PROFILE_ACTION`、`MESSAGE_COMPOSER`、`TOAST`。
- 服务层根据页面状态选择用户结果、主页操作区或 Toast 的局部区域；短期页面签名缓存与采样节流也已存在。
- 保留 `FULL` 的路径只用于需要全页语义的未知页、视频右侧栏/当前主页确认，或操作者主动诊断；这些路径不会全屏放大，且未被本轮为性能目的改动。
