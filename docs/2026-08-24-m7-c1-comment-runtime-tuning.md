# M7-C1b：评论运行时调参收敛

## 问题记录

- 当前错误现象：评论私信运行时把阶段超时、轮询、视频切换、评论列表上限、头像重试、直播退出、空白消息探测等有界预算集中在自身私有常量块，无法和已迁移的导航生命周期配置一并审阅。
- 稳定复现：审阅“进入评论用户主页 → 私信入口 → 空白消息安全探测”或“多视频评论列表 → 有界滚动 → 返回评论区”时，必须在运行时文件末尾反向查找多个参数来源。
- 当前预期行为：运行时的所有时序、次数和停止上限应从版本化只读配置层读取，特别是评论滚动、直播处理、私信入口和空白探测的安全上限不得放宽。
- 实际行为差异：行为目前正确，但预算分散，未来修改时容易遗漏关联的安全上限或在相似流程中出现不同默认值。

## 单一根因与最小修改

唯一根因假设：评论运行时缺少统一的参数来源，造成维护与安全审阅边界不清。

- 新增 `TuningConstants.CommentRuntime`，版本升至 `2`，迁移该运行时全部既有时序、重试次数、评论/直播停止上限与私有诊断目录值。
- `CommentPrivateMessageRuntime` 仅将原无前缀常量替换为对应配置读取；数值、循环条件、延时顺序、默认参数及现有安全停止分支完全保持不变。
- 不改变节点优先、OCR 辅助、几何校验、页面确认、空白消息拒绝检测、归一化手势坐标或私信动作。

## 验证

- `TuningConstantsTest`：通过。锁定启动预算，并覆盖评论入口重试、隐藏入口/OCR 上限、评论滚动/空滚动/返回次数和直播上限等关键安全值。
- `./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug`：通过。
- `git diff --check`：通过。

## 真机验证

- 设备：OnePlus NE2210，Android 16，序列号 `b33aa309`。
- 路径：安装 Debug APK → 保持任务停止 → 查询无障碍服务状态及诊断日志。
- 结果：改善。服务为 Bound/Enabled，Crashed 为空；日志显示无障碍服务连接与 OCR 初始化完成。
- 安全结果：没有任务启动、检查点恢复、页面内点击、滑动、空白消息探测或消息发送。

## 几何与 dp 归一化检查

- 本轮只迁移时序、次数、目录与既有手势时长的配置来源；未新增或修改 Android 几何尺寸、固定 px、坐标或屏幕比例。
- 现有评论手势仍使用归一化坐标，既有显式时长数值没有修改；无需新增 dp 归一化逻辑。
