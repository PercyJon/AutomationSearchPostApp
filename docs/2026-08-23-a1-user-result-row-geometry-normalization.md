# 2026-08-23：A1 用户结果行几何归一化

本记录遵循项目根目录 `AGENTS.md` 的小步修改、单一根因假设与同路径验证要求。

## 当前差异

- 现象：用户搜索结果的结构行、OCR 行高度、OCR 卡片间距和双帧稳定性曾使用固定像素阈值。
- 稳定复现：同一抖音用户结果页在不同屏幕高度或密度上运行；固定像素阈值会改变行的相对尺寸范围。
- 预期：保留已验证设备上的识别边界，同时让几何条件随实际可用屏幕尺寸缩放；不改变页面跳转、节点点击、OCR 证据顺序或手势。
- 实际：固定像素阈值将参考设备的物理像素假设带入其他设备，不能满足项目的 dp / 屏幕比例归一化约束。

## 本轮唯一根因假设

用户结果行的几何判断将设备相关尺寸写成固定像素，导致不同高度屏幕的安全接受区间不一致。

## 最小修改与影响范围

- `StructuralUserRowDetector`：将结构行高度改为屏幕高度比例区间；参考尺寸下的接受范围保持不变。
- `OcrUserResultRowDetector`：将 OCR 行高度改为屏幕高度比例区间；标题邻接、卡片上下留白、关注标签最小宽度与两帧漂移阈值统一由新增的 `OcrUserResultRowGeometry` 按实际屏幕宽高计算。
- `DouyinNavigationController`：删除两个未使用的历史行高常量。
- 不改变节点、OCR、几何验证、受限兜底的既有动作顺序；不变更任何点击坐标、滑动坐标或时序。

风险是识别边界附近的用户卡片可能被额外接受或拒绝。验证方案为：参考尺寸与短屏纯函数测试、相关检测器单测、完整 Debug 构建，以及相同的真机干跑路径。

## 验证结果

- 定向单测：结构行检测、OCR 用户行检测、用户结果身份确认与几何度量测试均通过。
- 完整检查：`./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug` 通过；`git diff --check` 无输出。
- 真机：OnePlus NE2210（Android 16 / SDK 36，设备序列号 `b33aa309`）；搜索 `designer`、匹配词“不错”、任一匹配、1 个视频 / 1 位用户、干跑。
- 已验证路径：语义搜索入口 → 提交 → 用户标签 → `USER_RESULTS` 后置确认；结构行节点不足时 OCR 回退被调用。
- 当前页面的首个卡片缺少可验证的关注标识，OCR 返回 `NO_FOLLOW_LABEL` 后按安全门结束；未进入用户主页、私信或空白探测。这是当前页面证据不足的安全结果，未为通过回归而放宽任何规则。

## 几何与归一化检查

- 新增和替换的生产几何均使用屏幕宽高比例计算；未新增固定 px 常量。
- 未将屏幕比例几何用于手势坐标，也未把坐标比例用于尺寸判断。
- 现有用户结果行清单中的固定像素高度和 OCR 像素命名阈值已移除。
