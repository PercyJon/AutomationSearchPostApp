# 2026-08-24：M8-E2 执行限额、任务授权与操作节流

本记录遵循项目根目录 `AGENTS.md` 的小步修改与同路径验证要求。

## 当前差异

- 现象：任务上限仍为 500；本地串行队列没有 999 项硬限制；没有跨任务的当日独立用户上限；远程任务没有本机任务 ID 白名单；无障碍节点动作、手势、返回与启动目标应用之间没有统一的最短间隔。
- 稳定复现：构造超出单任务、队列、当日唯一用户或未授权远程任务 ID 的输入；以及连续执行不同类型的无障碍动作。
- 预期：本机显式创建/启动的任务可执行；远程任务仅在本机白名单命中时可领取和启动；单任务最多 1000 人、队列最多 999 任务、当日最多 9999 名不同用户；所有会改变目标应用状态的自动动作相隔至少 3 秒。
- 实际：上述边界分别缺失或分散，且日额度不能只由会被裁剪的历史明细推导。

## 本轮唯一根因假设

执行授权、处理额度与动作节流没有独立的通用策略边界，导致不同任务入口无法一致地在实际操作前实施同一套限制。

## 最小修改与验证方案

- 新增纯策略：任务启动授权、单任务/队列/评论总人数限制、日独立用户额度与可注入时钟的操作节流器。
- 远程白名单只保存任务 ID；日额度账本只保存 SHA-256 用户指纹及保留时间，不保存昵称、账号、评论或消息内容。
- 在远程领取 UI 和控制器启动/恢复入口双重拒绝未授权远程任务；本地 UUID 任务保持显式授权。
- 在 B 端候选和评论候选真正点击前预留日额度；达到额度时暂停当前任务和本地队列，不触发下一任务，次日可从检查点继续。
- `GestureEngine` 统一覆盖节点点击、文本设置、回车、节点滚动、手势与全局返回；控制器在启动目标应用前也进入相同节流器。
- 不改变节点/OCR/几何/页面确认/私信入口/空白消息安全探测链路，不新增几何尺寸、固定 px 或坐标规则。

## 风险与验证

- 风险：节流覆盖遗漏可能导致局部操作快于 3 秒；额度预留位置错误可能跳过候选；授权判定错误可能误拒绝本地任务或误放行远程任务。
- 验证：纯 JVM 测试覆盖限额、白名单、本地/远程判定、跨日清理、去重、队列 999、评论总人数与节流时间；完整 Debug 单测、Lint、构建；真机只验证停止态安装、启动和授权拦截 UI，不启动已有任务或发送消息。

## 修复轮次 1

- 现象：首次编译时，评论配置的额度校验无法解析策略重载。
- 根因假设：`buildList` 的接收者遮蔽了 `CommentPrivateMessageConfig` 实例。
- 最小修改：在列表构建前固定配置引用，只将该引用传给策略。
- 复现验证：重新运行同一 Debug Kotlin 编译与 JVM 单测命令。

## 修复轮次 2

- 现象：新策略测试编译时引用了不存在的远程进度空对象工厂。
- 根因假设：测试夹具假定了模型提供默认工厂，但现有模型要求完整实例。
- 最小修改：仅在测试内构造零进度远程任务。
- 复现验证：重新运行同一策略测试命令。

## 修复轮次 3

- 现象：真机保留历史自动保存草稿时，新建 B 端任务仍显示旧默认值 20。
- 稳定复现：保留旧草稿数据，安装本阶段包后打开“B端私信”新建页，不输入人数。
- 预期：未填写人数显示并使用 1000。
- 实际：旧草稿缺少“默认/用户输入”来源，数值 20 被直接回填。
- 根因假设：历史自动保存的默认值未进行版本迁移。
- 最小修改：只在未完成草稿水合时将历史默认 20 迁移为 1000；其他已保存数值保持原样并限制在 1-1000。
- 复现验证：新增纯策略测试并使用同一 OnePlus 真机页面检查回填值。
