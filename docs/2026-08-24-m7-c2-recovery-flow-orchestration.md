# M7-C2h：恢复阶段动作编排拆分

日期：2026-08-24
范围：看门狗超时后的启动广告等待、搜索重试、页面恢复、用户选择、私信重试、跳过和暂停分派。

## 变更前记录

- 现象：恢复纯路由已独立，但控制器仍在超时恢复方法中直接分派各恢复动作。
- 稳定复现步骤：让首页、搜索入口、搜索结果、用户结果、主页或不支持阶段进入看门狗超时，并提供对应页面或启动广告标记。
- 预期行为：启动广告只等待，搜索重试保留恢复预算，页面恢复/用户选择/私信重试按既有页面条件执行，其余组合按原规则跳过或暂停。
- 实际差异：本轮为等价重构，没有线上故障；恢复动作分派无法在无障碍服务之外独立验证。

## 单一假设与最小修改

假设：将恢复路由的动作分派移入 `RecoveryFlow`，由控制器提供原有回调，可以固定既有恢复出口而不移动实际导航和安全策略。

- 新增 `RecoveryFlow`，只执行 `RecoveryFlowRouter` 已确认的分派。
- 控制器仍独占启动广告检测与只等待策略、恢复预算、页面动作、私信失败记录、节点/OCR/几何/手势和暂停。
- 启动广告标记存在时，流程仅重新进入有界观察，始终不会点击广告控件。

## 验证结果

- `RecoveryFlowTest` 覆盖启动广告等待、搜索重试、搜索入口复用、用户结果选择、主页私信重试、失败跳过和不支持阶段暂停。
- 自动化验证：`./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug` 与 `git diff --check` 通过。
- 真机 OnePlus NE2210（`b33aa309` / Android 16）：安装更新后无障碍服务为 Bound/Enabled、`Crashed services` 为空；本轮仅做停止态服务健康确认，不启动任务、不进行页面操作、空白探测或消息发送。

## 几何与安全检查

- 未新增 Android 几何尺寸、固定 px、坐标或手势；无需新增 dp 归一化逻辑。
- 启动广告仅等待，节点优先、OCR 辅助、几何校验、页面确认与私信安全门保持不变。
