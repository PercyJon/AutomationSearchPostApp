# M7-C2e：私信阶段动作编排拆分

日期：2026-08-24
范围：私信阶段页面观察后的既有完成、跳过、后置确认和风险暂停分派。

## 变更前记录

- 现象：控制器已拥有私信纯路由，但同一段页面观察代码仍直接执行所有私信阶段动作，阶段职责没有独立编排边界。
- 稳定复现步骤：向私信页、空白探测结果页、普通消息结果页或风险页提供既有页面类型。
- 预期行为：每种已存在的私信路由只能调用原有的一个完成、跳过、后置确认或暂停动作；无关页面不应被该阶段消费。
- 实际差异：本轮为等价重构，没有线上故障；原分派在控制器内，无法以无障碍服务之外的单测验证动作选择。

## 单一假设与最小修改

假设：将私信路由的动作分派移入 `PrivateMessageFlow`，控制器通过原有方法回调提供实际效果，可在不移动安全链路的前提下得到独立行为测试。

- 新增 `PrivateMessageFlow`，仅消费 `PrivateMessageFlowRouter` 已确认的路由，并调用控制器提供的既有回调。
- 控制器仍独占私信页面完成、空白探测、失败记录、后置确认、风险暂停、节点/OCR/几何/手势和消息安全策略。
- 回调参数和失败/暂停文案完全沿用原值。

## 验证结果

- `PrivateMessageFlowTest` 覆盖私信完成、受限跳过、普通消息失败、空白探测完成、探测风险暂停、后置确认与无关页面不消费。
- 自动化验证：`./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug` 与 `git diff --check` 通过。
- 真机 OnePlus NE2210（`b33aa309` / Android 16）：安装更新后无障碍服务为 Bound/Enabled、`Crashed services` 为空；本轮仅做停止态服务健康确认，不启动任务、不进行页面操作、空白探测或消息发送。

## 几何与安全检查

- 未新增 Android 几何尺寸、固定 px、坐标或手势；无需新增 dp 归一化逻辑。
- 空白消息探测、风险暂停和禁止真实内容发送的现有安全链路不变。
