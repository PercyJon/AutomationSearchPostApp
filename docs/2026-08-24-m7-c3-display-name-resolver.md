# 2026-08-24：M7-C3 统一显示名称解析器

本记录遵循项目根目录 `AGENTS.md` 的小步修改与同路径验证要求。

## 当前差异

- 现象：用户主页与私信页已各自具备候选名称解析，但控制器分别编排稳定确认、OCR 门控和来源选择。
- 稳定复现：主页先从无障碍节点提取名称并二次确认，必要时才进行局部 OCR；私信页先使用无障碍节点，缺失时才进行局部 OCR。两条路径的持久化代码重复表达“无障碍优先”。
- 预期：页面级候选提取和几何过滤保持不变，由单一入口仲裁来源、OCR 门控与主页名称稳定确认。
- 实际：解析契约分散在控制器和两个页面解析器之间，无法以一个单元测试确认来源优先级，也容易在后续维护时让两个页面偏离。

## 本轮唯一根因假设

显示名称的来源优先级与控制器的页面动作编排混合，导致同一安全规则没有唯一可测试的归属。

## 最小修改与验证方案

- 新增 `DisplayNameResolver` 作为唯一解析入口：按页面表面委托既有候选解析器，统一 OCR 门控、无障碍优先仲裁及主页二次确认。
- 控制器只调用该入口；不改变候选解析器的节点/OCR/几何规则、截图区域、持久化字段、点击、手势、导航或消息发送逻辑。
- 风险：抽取时可能误改变“无障碍优先”或主页二次确认的次数。
- 验证：新增统一入口的页面委托、来源仲裁、OCR 门控和二次确认单测；运行完整 Debug 单测、Lint、构建及真机安全回归。

## 验证结果

- 定向测试：新增 `DisplayNameResolverTest`，覆盖页面表面委托、无障碍优先仲裁、OCR 回退、主页二次一致确认及页面特定 OCR 门控；既有 `ProfileDisplayNameResolverTest`、`DirectMessageDisplayNameResolverTest`、`DisplayNameResolutionPolicyTest` 同时通过。
- 完整检查：`./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug` 通过；`git diff --check` 无输出。
- 真机：OnePlus NE2210（Android 16，序列号 `b33aa309`）安装 Debug 包后，无障碍服务可正常绑定且 `Crashed services` 为空。设备存在一项历史恢复状态并已在进入动作前停止服务；未点击抖音控件、未输入或发送消息。C3 不修改页面跳转、点击、手势或恢复策略，因此没有以历史任务伪造行为回归。
- 几何检查：未新增或修改 Android 几何尺寸、固定 px、坐标点击或手势时长；不涉及新增 dp 归一化项。既有页面级节点/OCR/几何筛选保持原样。
