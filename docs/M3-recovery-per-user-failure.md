# M3-Recovery：私信流程可恢复失败

## 目标

提高任务连续运行能力。单个用户的私信入口、输入框、发送动作或发送结果异常，不再把整个任务停在“需要人工处理”；系统会记录失败、返回用户列表并继续下一位。

## 本轮变更

- 私信输入框最多尝试 3 次，每次间隔 350ms；仍无法输入时记录 `MESSAGE_SEND_FAILED`。
- 私信发送按钮最多尝试 3 次；按钮或提交动作不可用时记录当前用户失败。
- 进入私信页使用现有 12 秒 watchdog；超时后当前用户记录失败并跳过。
- 空消息探针在 18 次结果观察结束后，若未检测到“不能发送空白消息”，记录失败并跳过，不再人工暂停。
- 非空消息发送结果在有限观察窗口结束后记录失败并跳过。
- 单用户失败返回结果列表时，优先定位上一用户之后的可见行；必要时才滚动并等待列表稳定。
- 连续“回关/不可私信”不再因累计次数触发人工暂停。
- 用户身份暂时不可解析时跳过该行；无法恢复结果列表时才将整项任务标记为 `FAILED`。
- 任务统计不再把 `IN_PROGRESS` 计入“已处理”，新增真实失败计数；失败详情仍保留用户、时间、页面和原因。

## 仍需人工接管的情况

- 验证码、风控/安全提示、登录失效。
- 任务无法恢复到用户结果列表的任务级导航故障。
