# 2026-08-23：P1-B 评论匹配统计

本记录遵循项目根目录 `AGENTS.md` 的小步修改与同路径验证要求。

## 当前差异

- 现象：评论任务日志只有当前视口的 `candidate_count`；任务详情无法显示读取了多少评论正文、匹配到多少正文，以及最终形成多少可安全处理候选。
- 稳定复现：创建任一带评论匹配词的评论私信任务，任务记录页仅显示处理、跳过、失败等用户结果，不显示匹配统计。
- 预期：任务详情以不含原文、不含账号信息的累计数字展示“已读取正文 / 命中正文 / 可安全处理候选”。
- 实际：匹配过滤在 `CommentCandidateExtractor` 内完成，未命中的正文不再出现在提取结果；`AutomationStore` 也没有用于持久化这类统计的字段。

## 本轮唯一根因假设

候选提取结果没有保留匹配前的正文数量，且运行时没有将无敏感文本的统计聚合写入任务历史。

## 最小修改与验证

- 提取结果只新增整数统计：已读取正文、命中正文、可安全处理候选；不保存正文或 OCR 文本。
- 同一视口指纹只上报一次，避免重复观察把累计值放大。
- 任务历史持久化这些整数，并仅在评论任务详情页展示。
- 单元测试覆盖统计口径与历史序列化兼容；随后运行既有 Debug 单测、Lint 与构建。真机仅使用干跑，不点击评论头像或私信入口。

## 验证结果

- 单测：`CommentPrivateMessageModelsTest` 通过，覆盖提取统计字段不携带评论文本；既有评论提取测试保持通过。
- 完整检查：`./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug` 通过，随后 `git diff --check` 无输出。
- 真机：OnePlus NE2210（Android 16 / SDK 36，设备序列号 `b33aa309`）；使用搜索词 `designer`、匹配词“不错”、全部匹配、1 个视频 / 1 位用户、空白消息安全探测。
- 真机结果：详情页显示“已读取正文 4 · 命中正文 2 · 可安全处理 2”。首条评论的几何信息不完整，既有首行安全门按预期终止任务；没有点击评论用户、没有进入私信、没有发送消息。
- 隐私与兼容：任务历史只持久化三个非负整数；旧记录缺少这些字段时按 0 读取。未新增几何尺寸、像素阈值或坐标点击逻辑，因此不涉及新的 dp 归一化项。
