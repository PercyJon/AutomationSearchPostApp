# 待办、任务详情与诊断页面视觉收敛记录

## 开始前记录

- 当前现象：待办页的底部“开始任务”仍为大号胶囊按钮；任务记录详情中标题、概览文本和用户结果卡的层级偏大；开发诊断页沿用旧的默认卡片、输入、芯片和操作按钮样式。
- 稳定复现：登录后进入“待办”；或“我的 → 任务记录 → 任一记录”；或“我的 → 服务与诊断”。
- 预期行为：保留全部任务、诊断和控制能力，仅统一为紧凑圆角卡片、输入、芯片和按钮的展示比例，且不触发或修改任何任务状态。
- 实际差异：操作页面与已完成的账户中心、表单、设置及记录列表不一致，阅读和操作密度偏低。
- 本轮唯一假设：问题只来自 Compose 展示组件的尺寸、圆角和文本层级；任务执行、诊断命令、记录数据、筛选与导航状态不需要修改。
- 修改边界：仅修改 `HomeScreen.kt` 和 `DiagnosticsScreen.kt` 的视觉属性及静态说明文案；不修改任何 `AutomationCommand` 派发条件、任务快照、记录模型、日志、无障碍、OCR 或网络逻辑。

## 验证计划

1. 编译、单元测试和 Android lint。
2. 真机只读验证“待办 → 我的 → 任务记录 → 记录详情 → 返回 → 服务与诊断”。
3. 不点击开始、暂停、继续、停止、截图/OCR、导出节点树、复用、重试或系统设置入口；结束后停止 App 并返回系统桌面。

## 实施结果

- 结果：**改善**。待办的固定底部“开始任务”改为 46dp 高、8dp 圆角；任务记录详情和单用户结果卡统一为紧凑 12dp 圆角卡片、14dp/12dp 内边距与更清晰的标题层级。
- 开发诊断页改为标准返回箭头、统一描边卡片、50dp 输入、34dp 预设芯片和 46dp 操作按钮；诊断状态、控制、截图/OCR、节点树和日志入口的回调保持原样。
- 所有任务控制、诊断命令、复用、重试、记录数据和无障碍行为均未修改。

## 验证结果

- `git diff --check` 通过。
- `./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug -PautomationApiEndpoint=<受管 HTTPS 服务地址>` 通过（55 个 Gradle 任务）；仅保留既有 Material/图标弃用警告。
- **真机 OnePlus NE2210 / b33aa309 / Android 16**：验证“首页 → 待办 → 我的 → 任务记录 → 已完成记录 → 返回 → 服务与诊断”。待办底部按钮、记录概览、用户结果卡、诊断状态、搜索输入、预设芯片、控制按钮和采集诊断区域均正常显示。
- 测试中没有点击开始、暂停、继续、停止、截图/OCR、导出节点树、复用、重试或系统设置入口；没有调用抖音；结束后 App 已停止并返回系统桌面。

## 几何与兼容性检查

- 新增/变更视觉尺寸均为 Compose `dp`（50dp 输入框、46dp 按钮、34dp 芯片、12dp/8dp 圆角、14dp/12dp 卡片留白、92dp 诊断键值标签宽度）；没有新增固定 px、自动化坐标、OCR 几何或设备相关手势时长。
- 诊断关键词继续使用 Material `AssistChip` 语义，任务/诊断按钮继续使用原有 Material 组件和现有回调；仅收敛视觉比例。
