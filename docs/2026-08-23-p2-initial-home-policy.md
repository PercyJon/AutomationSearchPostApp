# 2026-08-23：P2-C 启动页 HOME 归一化策略抽取

本记录遵循项目根目录 `AGENTS.md` 的小步修改与同路径验证要求。

## 当前差异

- 现象：启动观察和有界启动恢复分别维护“未知页、无临时遮罩、已验证搜索入口”应视为 HOME 的同一判定。
- 稳定复现：在抖音稀疏首页只暴露右上搜索入口时，启动观察与恢复都会执行该判定。
- 预期：两条路径的页类型、置信度和各自诊断原因一致，不引入新的页面动作。
- 实际：相同条件分散在控制器两处；今后任一处调整可能让观察与恢复语义漂移。

## 本轮唯一根因假设

启动页 HOME 归一化作为纯判定与控制器编排代码混合、且存在两个实现位置，增加了后续语义漂移风险。

## 最小修改与验证

- 新增 `InitialHomeSurfacePolicy`，只接收已有页类型、临时遮罩结果、搜索入口验证结果与诊断原因，返回页类型判定；控制器仍在原调用时机计算节点和遮罩证据。
- 不修改搜索、点击、手势、评论、私信、空白探测或恢复动作顺序。
- 风险：稀疏首页可能被错误归一化为 HOME。
- 验证：策略单测覆盖可归一化、临时遮罩阻断、已识别页面保持不变；完整 Debug 单测、Lint、构建；真机干跑通过搜索、主页、作品、评论面板到候选选择。

## 验证结果

- 单测：`InitialHomeSurfacePolicyTest` 通过。
- 完整检查：`./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug` 通过，`git diff --check` 无输出。
- 真机：OnePlus NE2210（Android 16 / SDK 36，设备序列号 `b33aa309`）；搜索词 `designer`、匹配词“不错”、任一匹配、1 个视频 / 1 位用户、干跑。
- 关键日志：稀疏首页的语义搜索入口被归一化为 `HOME`（置信度 `0.78`）；随后完成目标主页、首个作品、评论面板与候选读取，并以 `comment_dry_run_candidate_selected` / `comment_runtime_terminal [outcome=COMPLETED]` 结束。
- 安全结果：未进入评论用户主页、私信页或空白消息探测；未新增 Android 几何尺寸、固定 px、坐标点击或手势逻辑，因此无新增 dp 归一化项。
- 结果：改善。启动页归一化现由单一、可单测的策略所有；控制器保留证据采集和状态编排。
