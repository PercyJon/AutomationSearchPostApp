# 评论指定用户首行稳定性修复记录（第 1 轮）

## 当前错误现象

“评论私信 → 搜索指定用户”任务在已进入抖音“用户”结果页后，提示“目标用户搜索结果缺少可验证的行结构”并结束；不会进入目标用户主页、视频或评论区。

## 稳定复现步骤

1. 创建评论私信任务：目标用户“室内设计师”，匹配词留空，视频数上限 2、每个视频用户数 5，空消息安全探测模式。
2. 启动任务，等待搜索提交并切换到“用户”标签。
3. 观察任务在首次用户结果页结束。

## 当前预期行为

“用户”标签的结果容器仍在切换时，应有上限地等待可见结果树稳定；随后仅在结构校验，或两次一致的 OCR 加几何校验成功后，才进入首个目标用户主页。始终不得依据未验证坐标点击。

## 实际行为差异

失败时的节点诊断显示搜索框、标签栏可见，而 `ViewPager` 下的用户结果容器均标记为隐藏且横向范围为 0；实际屏幕已有用户卡片。现有两次 120ms 快速探测后立即进入 OCR，因此可能在首帧尚未稳定时就安全终止。

## 第 1 轮根因假设

首次切换到“用户”标签后，无障碍树比视觉结果晚一帧或多帧提交；快速探测窗口不足，导致结构和 OCR 均读取到过渡帧，而不是稳定后的首张用户卡。

## 最小修改与验证方案

仅对“搜索指定用户”的首次结果页：当两次快速结构探测仍没有可见行时，增加一次有上限的稳定等待，直到用户结果 `ViewPager` 不再处于隐藏过渡状态；之后复用既有结构检测及两次 OCR/几何一致性校验。不会改变 B 端任务、列表翻页、点击目标或空消息安全链路。以同一“室内设计师”任务真机复现，验证可进入经验证的目标主页；随后用悬浮窗暂停、恢复、停止测试，且在任何评论用户或私信动作前停止。

## 第 1 轮结果：改善

- 新增的过渡态检测只观察 `ViewPager` 与可见子树，不新增点击坐标或几何阈值；最多 3 次 × 350ms，结果树一旦可见立即结束等待。
- **真机 OnePlus NE2210 / b33aa309 / Android 16**：同一“室内设计师”任务先记录 `p0_user_results_viewport_settle`，随后两次 OCR 卡片校验一致，安全进入目标用户主页、首个视频和评论面板；不再出现“缺少可验证的行结构”失败。
- 单元测试与调试构建均通过；未发送真实消息。
