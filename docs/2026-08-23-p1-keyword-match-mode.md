# 2026-08-23：P1-A 评论匹配方式

本记录遵循项目根目录 `AGENTS.md` 的小步修改与同路径验证要求。

## 当前差异

- 现象：评论匹配词只能以 `|` 分隔，并固定采用“任一词包含即命中”的 OR 语义。
- 稳定复现：以 `价格|优惠` 创建评论私信任务；正文只包含“价格”时会命中，且没有选择“必须同时包含价格和优惠”的入口。
- 预期：在不改变既有任务行为的前提下，操作者可明确选择“任一匹配（OR）”或“全部匹配（AND）”。匹配仍只针对已验证的评论正文，绝不影响头像定位、页面跳转或点击策略。
- 实际：`CommentKeywordMatcher.matches`、任务配置和快照均未保存匹配方式，因此所有非空词列表均按 OR 处理。

## 本轮唯一根因假设

匹配方式没有作为任务配置的一部分冻结并传递给候选提取器，运行时只能使用硬编码的 OR 语义。

## 最小修改与验证

- 新增匹配方式枚举，默认 OR，保障既有草稿、历史任务与远程快照的兼容性。
- 仅把该配置传至评论正文匹配函数和现有候选提取器；不修改 OCR、几何阈值、Accessibility 点击、手势或恢复逻辑。
- 使用 JVM 单元测试覆盖 OR 兼容、AND 必须全词命中、任务快照冻结；随后运行既有 Debug 单测、Lint 与构建。
- 真机验证复用现有 Debug 回归预置，并只允许 `dryRun=true`：以 `ALL` 和经验证的无匹配条件运行，预期零命中且不点击评论头像或私信入口。

## 验证结果

- JVM：`CommentPrivateMessageModelsTest` 通过，覆盖既有 OR 兼容、ALL 必须同时命中全部规范化词，以及任务快照冻结匹配方式。
- 构建：`./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug` 通过；`git diff --check` 通过。
- 真机：OnePlus NE2210（Android 16 / `b33aa309`）。OR 干跑以单个真实匹配词读取到 4 位安全候选，并在 `comment_dry_run_candidate_selected` 后完成；没有点击评论头像、进入私信或发送内容。
- 真机：ALL 双词干跑到达同一评论面板后读取为 0 位候选，未出现评论头像或私信动作。该次空候选重读仅执行 1 次后因即时页面上下文不完整进入超时，故只作为“AND 未产生错误候选”的安全证据，不能作为空候选终态的验收。
- 对照：同一设备上的 OR 无匹配干跑可完成 3 次首屏重读后以 0 候选正常结束。空候选终态的偶发超时是独立观察项，本轮未修改恢复、OCR、候选几何或点击链路。
- 真机：按操作者指定的评论匹配词、`designer` 搜索入口与 ALL 模式执行干跑。提取器识别到 1 位候选，但首个可见头像行与首个完整候选不在同一行；既有首行安全门正确以 `comment_first_row_unresolved` 终止，未跳过首行、未点击评论头像、未进入私信、未发送内容。该结果不允许通过放宽首行规则来追求命中率。
