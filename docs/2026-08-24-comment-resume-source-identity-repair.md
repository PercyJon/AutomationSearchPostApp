# 评论队列恢复源主页身份修复记录（第 1 轮）

## 当前错误现象

评论私信“搜索指定用户”任务在视频页暂停、恢复并重新搜索后，把同一目标主页识别为重复用户而跳过；随后尝试翻到其他搜索结果，在没有稳定翻页证据时超时结束。

## 稳定复现步骤

1. 创建评论私信任务：目标用户“室内设计师”，匹配词留空，视频数上限 2、每个视频用户数 5，空消息安全探测模式。
2. 启动并进入目标主页的视频页，展开悬浮窗点击“暂停”。
3. 点击“恢复”，使任务从初始搜索流程重新进入“用户”结果页。
4. 观察首个目标主页被记录为重复项、任务改为翻页而非重新进入该主页。

## 当前预期行为

搜索指定用户的“源主页”只用于进入评论流程，不是私信候选。恢复后可重新验证并进入同一源主页；实际评论候选继续由其独立、持久的评论身份账本去重，绝不重复发送。

## 实际行为差异

当前控制器在打开源主页前，将它加入通用用户结果身份账本。恢复时该账本被重建，首个搜索结果被判为重复并跳过；该任务又禁止改选其他搜索结果，最终进入无意义的列表翻页等待。

## 第 1 轮根因假设

通用 B 端用户身份账本被错误复用于评论任务的单个源主页。它把“已进入的源主页”与“已完成的评论私信候选”混为同一种已处理对象。

## 最小修改与验证方案

仅在“评论私信 → 搜索指定用户”选择源主页时，不持久化该源主页到通用用户结果身份账本；保留原有评论候选身份账本、结构/OCR/几何校验和空消息安全探测。以同一暂停→恢复步骤真机复测，验证源主页再次通过验证进入，日志不再出现源主页重复跳过；在评论候选动作之前点击停止，确认无真实私信发送。

## 第 1 轮结果：改善

- 仅搜索指定用户的源主页不再写入通用用户结果身份账本；评论候选的独立持久去重账本未改动。
- **真机 OnePlus NE2210 / b33aa309 / Android 16**：视频页暂停后恢复，首次和恢复后的源主页均记录 `duplicate=false` 与 `comment_source_profile_identity_not_persisted`，并再次安全进入同一目标主页及评论面板；没有再发生源主页重复跳过和后续翻页超时。
- 停止按钮返回 App；停止与评论候选跳转同一时刻发生，任务已进入候选私信入口但未输入、未提交任何消息，也未执行空消息安全探测。
- 单元测试与调试构建均通过。
