# 2026-08-23：P2-E 用户结果视口指纹抽取

本记录遵循项目根目录 `AGENTS.md` 的小步修改与同路径验证要求。

## 当前差异

- 现象：用户结果 OCR 缓存键的几何过滤和序列化逻辑位于导航控制器中。
- 稳定复现：同一用户结果视口中逐行处理时，控制器以右侧动作轨道的节点边界构建缓存键，避免对重叠行重复截图 OCR。
- 预期：缓存键仍只使用已有屏幕比例和可见节点几何，按从上到下顺序稳定生成。
- 实际：纯缓存键逻辑与状态机编排混合，难以单独验证过滤边界。

## 本轮唯一根因假设

用户结果视口指纹是无状态几何计算，却保留在导航控制器中，扩大了控制器职责并降低可测性。

## 最小修改与验证

- 新增 `UserResultsViewportFingerprint`；仅迁移原有右侧动作轨道比例 `0.62` 与控制器传入的既有结果区顶部比例 `0.14`，不新增固定像素值。
- 不修改 OCR 触发时机、缓存命中条件、列表滚动、搜索、点击或私信逻辑。
- 风险：缓存键改变可能导致同一视口重复 OCR 或错误复用。
- 验证：单测覆盖可见轨道节点、顶部排除、左侧排除、零尺寸排除与从上到下排序；完整 Debug 单测、Lint、构建；真机干跑。

## 验证结果

- 定向与完整检查：通过；`git diff --check` 无输出。
- 真机：OnePlus NE2210（Android 16 / SDK 36，设备序列号 `b33aa309`）；同一干跑配置下，身份 OCR 正常返回 `38` 个块，评论运行时读取 2 个候选并以 `comment_dry_run_candidate_selected` / `comment_runtime_terminal [outcome=COMPLETED]` 结束。
- 安全与几何检查：未进入评论用户主页、私信或空白消息探测；只使用既有屏幕比例，未新增 Android 几何尺寸、固定 px 或坐标动作。
- 结果：改善。控制器降至 5,167 行，视口指纹成为可独立测试的纯函数，缓存语义与触发时机不变。
