# M7-C1a：导航生命周期调参收敛

## 问题记录

- 当前错误现象：导航启动的等待、观察、OCR 重试与基础看门狗参数同时散落在 `DouyinNavigationController` 的私有伴生对象中；维护者无法从统一入口审阅这些有界预算的用途和版本。
- 稳定复现：审阅“启动抖音后等待首页、轮询节点树、未知页 OCR 重试、OCR 页面稳定确认、阶段超时”任一流程时，需要在 5,000 行控制器中寻找多个常量及其调用点。
- 当前预期行为：这些生命周期预算应从具名、只读、带版本和边界说明的配置层读取，数值及调用顺序不能改变。
- 实际行为差异：虽然现有行为正确，但参数来源分散，今后调整容易遗漏关联的上限或安全注释。

## 单一根因与最小修改

唯一根因假设：导航生命周期参数没有共享配置入口，导致维护边界不清。

- 新增 `TuningConstants.NavigationLifecycle`，版本为 `1`，收敛基础阶段超时、启动超时、启动稳定等待、节点观察窗口和未知页 OCR 重试预算。
- 控制器直接引用该配置；常量值、日志值、延时、次数、OCR 门控、页面判定和动作顺序均保持不变。
- 本轮不把远程配置接入任何自动化安全策略；配置层仍完全由代码控制。节点/OCR/几何/页面确认和消息安全门不变。

- 不存在 dp 归一化新增项；既有比例坐标与 dp 规则保持不变。
