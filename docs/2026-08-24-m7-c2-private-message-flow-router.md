# M7-C2b：私信阶段路由拆分

## 问题记录

- 当前错误现象：普通私信、消息结果与空白消息探测三个等待阶段的页面分流与实际发送/跳过/暂停副作用同处于导航控制器中。
- 稳定复现：审阅已进入私信页、空白消息被平台拒绝、私信受限、消息发送失败或仍停留用户主页时的下一步动作，必须在大型控制器中阅读混合分支。
- 当前预期行为：私信阶段的“阶段 + 页面类型 → 既有处理类别”可独立覆盖；控制器继续拥有任何发送、空白探测、记录、暂停和页面动作。
- 实际行为差异：原行为正确，但分流难以表格化回归，后续拆分时存在混淆普通消息失败与空白探测失败处理文案的风险。

## 单一根因与最小修改

唯一根因假设：私信阶段的纯路由和带副作用的安全处理混合在控制器内。

- 新增 `PrivateMessageFlowRouter`，仅返回既有处理类别：完成到消息页、完成空白探测、私信受限跳过、两类消息失败跳过、入口后置确认和风险暂停。
- 控制器仍调用原有 `completeAtMessagePage`、`completeEmptyMessageProbe`、`skipRestrictedUser`、`skipMessageSendFailure`、`scheduleMessageEntryPostconditionCheck` 与 `pause`。
- 真实消息发送、空白消息探测、节点操作、OCR、页面确认和风险页的全局优先暂停均未迁移或改变。

## 稳定链路影响说明

- 修改原因：为 C2 的 `PrivateMessageFlow` 建立可单测的阶段边界。
- 影响范围：仅三个私信等待阶段的页面分流表达。
- 风险：路由可能错误复用失败原因或绕过风险暂停。
- 验证方案：表驱动单测锁定每个终态/失败/风险映射；完整构建；真机停止态服务回归。风险页在全局安全门已优先返回这一既有顺序保持不变。
