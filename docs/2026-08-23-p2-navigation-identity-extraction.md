# 2026-08-23：P2-A 导航控制器身份比对抽取

本记录遵循项目根目录 `AGENTS.md` 的小步修改与同路径验证要求。

## 当前差异

- 现象：`DouyinNavigationController` 已有 5,413 行，同时承担页面状态机、动作调度、OCR 协作、任务生命周期和搜索结果身份比对。
- 稳定复现：阅读远程续跑与用户结果翻页逻辑时，身份键重建、去重和锚点匹配规则被夹在页面动作代码之间，难以独立审查或测试。
- 预期：不改变任何导航行为的前提下，让无副作用的身份比对规则拥有独立边界和独立单测。
- 实际：这一组规则只能作为控制器私有方法随状态机一同阅读，控制器的职责边界过宽。

## 本轮唯一根因假设

纯身份比对策略与有状态的导航编排共处同一个超大类，导致耦合和回归审查成本偏高。

## 最小修改与验证

- 仅抽取远程锚点身份构建、去重匹配、续跑锚点匹配和文本规范化辅助规则到独立对象。
- 保持原有调用时机、返回值、字符串原因码和任务状态字段不变；不改 Accessibility、OCR、几何、点击、手势或页面转换。
- 风险：OCR 容错去重或续跑锚点匹配结果发生变化，可能导致重复处理或不必要停止。
- 验证：新增等价性单测，运行现有 Debug 单测、Lint、构建及同一条真机空白消息安全探测路径；任何发现的差异先停止并回退到最小诊断。

## 验证结果

- 单测：新增 `UserResultIdentityMatcherTest` 通过，覆盖账号句柄去重、OCR 裁切名称的续跑锚点、历史回退键与泛化 UI 标签排除；既有评论匹配与候选提取单测同时通过。
- 完整检查：`./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug` 通过，`git diff --check` 无输出。
- 真机：OnePlus NE2210（Android 16 / SDK 36，设备序列号 `b33aa309`）；使用搜索词 `designer`、匹配词“不错”、全部匹配、1 个视频 / 1 位用户、空白消息安全探测。
- 真机路径：搜索入口 → 搜索结果 → 目标主页 → 首个作品 → 评论面板。首行评论结构仍无法完整验证，任务按既有安全门终止；未点击评论用户、未进入私信、未发送消息。
- 结果：改善。身份匹配规则已从控制器抽出，控制器由 5,413 行降至 5,235 行；页面状态、动作、OCR、几何和手势逻辑无行为变化。
- 几何检查：本轮未新增 Android 几何尺寸、像素阈值或坐标逻辑，不涉及新增 dp 归一化项。
