# 2026-08-23：P2-B 目标窗口读取职责抽取

本记录遵循项目根目录 `AGENTS.md` 的小步修改与同路径验证要求。

## 当前差异

- 现象：`DouyinNavigationController` 同时负责编排状态机和读取当前抖音无障碍窗口。
- 稳定复现：诊断、超时恢复、搜索、点击前验证都会调用同一窗口读取逻辑；该逻辑与任务状态无关，却嵌在 5,000 余行控制器内。
- 预期：将“活跃窗口优先、可见抖音窗口兜底、节点回收”的无状态职责独立，调用时机和返回值保持不变。
- 实际：窗口读取责任与导航动作混合，难以独立审查遮罩场景的资源回收。

## 本轮唯一根因假设

无状态的目标窗口快照读取与有状态导航编排共处，扩大了控制器职责边界。

## 最小修改与验证

- 只抽取当前窗口读取器；保留控制器原方法名作为单行委托，所有调用时机不变。
- 风险：应用内遮罩短暂夺取活跃窗口时，兜底窗口选择或节点回收发生差异。
- 验证：完整 Debug 单测、Lint、构建；真机以干跑方式验证搜索、目标主页、作品和评论面板路径，不进入评论用户主页或私信页。

## 验证结果

- 完整检查：`./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug` 通过，`git diff --check` 无输出。
- 真机：OnePlus NE2210（Android 16 / SDK 36，设备序列号 `b33aa309`）；使用搜索词 `designer`、匹配词“不错”、1 个视频 / 1 位用户、干跑。
- 真机路径：搜索入口 → 搜索结果 → 目标主页 → 首个作品 → 评论面板 → 首位可操作候选确认。任务完成且未进入评论用户主页、私信页或空消息探测。
- 结果：改善。窗口快照读取已独立，控制器从 5,235 行降至 5,206 行；活跃窗口优先、可见目标窗口兜底和节点回收顺序不变。
- 几何检查：未新增 Android 几何尺寸、固定 px、坐标点击或手势逻辑，不涉及新增 dp 归一化项。
